# 疯狂电路完赛

> 第 21 届全国大学生智能车竞赛「疯狂电路」赛道完赛代码与技术方案。

## 📋 项目简介

本项目是智能车竞赛「疯狂电路」赛道的完整实现方案，采用**英飞凌 TC264 单片机** + **MT9V03X 总钻风摄像头**，通过视觉识别与双环 PID 控制，实现缩微赛道上的高速循迹、精准转向、动态前瞻等功能。

### 控制架构：双环级联 PID + 动态前瞻

#### 1. 速度环（内环，3ms 周期）
速度环是底层执行单元，负责将目标速度转化为电机 PWM 输出：

```
编码器测速 → 速度误差 = 目标速度 - 实际速度 → PID 计算 → PWM 输出
```

**参数配置：**
- `Kp = 4.0`：比例增益（强磁电机需要 40-43，本项目经地推测试确定）
- `Ki = 0.2`：积分增益（消除稳态误差，避免过大导致打滑）
- `Kd = 0`：微分项未启用（编码器噪声较大时可适当添加 0.3-0.5）

**调试技巧：**
- **地推测试**：手推车感受阻力，Kp=40 时有明显阻力且放开后不自转为佳
- **阶跃响应测试**：给定左轮 30、右轮 50 的速度指令，观察左右轮速度跟随效果
- **串口调参**：通过 Vofa 上位机实时调整 PID 参数，观察速度波形收敛情况

**速度环与位置环的关系：**
位置环（转向环）输出转向修正量 `steer`，叠加到基础速度 `base_speed` 上形成左右轮差速：
```
左轮目标速度 = base_speed + steer
右轮目标速度 = base_speed - steer
```
速度环独立跟踪各自的目标速度，实现差速转向。

#### 2. 转向环（外环，10-12ms 周期）
转向环根据视觉偏差计算转向修正量，输出给速度环作为差速指令：

```
图像误差 → 转向 PID → 转向输出 steer → 左右轮差速
```

**参数配置：**
- `steer_kp = 25`：基础比例增益
- `steer_kp2 = 1.0`：非线性项（误差平方项，急弯时增强响应）
- `steer_kd = 2.0`：微分阻尼（抑制转弯后的振荡）
- `steer_gkd = 35`：陀螺仪阻尼（高速时利用角速度稳定车身）

**调试策略：**
- **只开 P**：调节 `kp` 使直道稳定、弯道能跟住
- **加 kp2**：增强急弯响应，但过大会导致直道抖动
- **加 kd**：平滑转弯后的回正过程，消除振荡
- **加 gkd**：高速时（base_speed > 120）加入陀螺仪反馈，提升稳定性

#### 3. 动态前瞻算法（上帝之光）
前瞻距离根据图像质量动态调整，实现速度自适应控制：

```c
TowPoint = 18 - WhiteGain;  // WhiteGain 越大（白线多）→ 前瞻越近
```

**工作原理：**
- **直道**：赛道清晰可见，WhiteGain 大 → 前瞻距离短 → 快速响应小偏差
- **弯道**：视野受限，WhiteGain 小 → 前瞻距离长 → 提前预判转向
- **丢线**：白线消失，前瞻自动拉长，保持历史轨迹跟随

**核心算法：**
- 在前瞻点提取 20 个采样点，用高斯权重（中心 0.450，边缘 0.020）计算加权偏差
- 偏差送入转向 PID，输出转向修正量

### 视觉处理：分区大津法 + Gamma 校正

#### 图像预处理（200-700μs）
1. **Gamma 校正**（γ=0.5）：压缩高亮区域，拉伸暗部对比度，抗反光
2. **分区大津法**：
   - 远区（上 1/3）：阈值 = OTSU - 2（降低阈值，防止远处丢线）
   - 中区（中 1/3）：阈值 = OTSU - 1
   - 近区（下 1/3）：阈值 = OTSU + 1（提高阈值，过滤近处噪声）

#### 边线提取（三向扫描）
- **正向扫描**（从下往上）：提取主赛道中线
- **左右扫描**：检测边界，辅助拐点判断
- **填充断线**：中线断裂时用历史数据三次样条插值

#### 拐点检测（矩形框二次验证）
1. 列坐标跳变超过阈值 → 疑似拐点
2. 多拐点时保留跳变幅度最大的
3. 在拐点周围画矩形框，检查框内黑白像素比例，确认真实性

### 控制环时序设计

```
外环（转向）：12ms  ← 与图像采集同步
图像采集：    10ms  ← MT9V03X 摄像头帧间隔
角速度环：     6ms  ← 陀螺仪更新频率
速度环：       3ms  ← 编码器采样周期（最快，内环）
```

**时序关系：**
- 图像处理时间实测：200-700μs（目标 <2ms，留出余量给其他任务）
- 空帧处理：0.047ms（无图像数据时的快速退出）
- 外环周期 12ms 略大于图像周期 10ms，确保每次转向计算都基于新图像
- 速度环 3ms 是角速度环 6ms 的 1/2，满足内环频率 ≥ 外环频率 × 5 的工程经验

**已知问题：**
- 极端强光/逆光环境下，即使使用 Gamma 校正 + 分区大津法，阈值分割效果仍会下降
- 图像处理时间在 200-700μs 跳动，可能与 CPU 缓存命中率或中断抢占有关

## 🚀 使用说明

### 开发环境配置

1. 安装 **AURIX Development Studio (ADS)**（英飞凌官方 IDE，基于 Eclipse）
2. 下载并导入**逐飞科技 TC264 开源库**（已包含在 `Libraries/` 中）
3. 连接 **DAP-Link** 或 **ULINK** 调试器到 TC264 开发板

### 编译与下载

1. 在 ADS 中打开 `code/` 工程
2. 选择 `Release` 或 `Debug` 配置
3. 点击「Build Project」编译
4. 点击「Debug」下载到开发板并运行

### 参数调节

核心参数在 `USER/config.h` 中配置：

- **图像阈值**：`THRESHOLD_OFFSET`（大津法偏移量）
- **PID 参数**：`Kp`、`Kd`、`Ki`（方向环与速度环）
- **拐点检测灵敏度**：`CORNER_THRESHOLD`（列坐标跳变阈值）
- **速度设定**：`SPEED_STRAIGHT`（直道）、`SPEED_CORNER`（弯道）

### 调试工具

#### 串口上位机调参（Vofa+ 波形观测）

**硬件连接：**
- TC264 UART0 → USB-TTL 模块 → 电脑
- 波特率：115200（在 `uart.c` 中配置）

**Vofa+ 配置步骤：**
1. 下载 Vofa+（开源串口波形显示工具）
2. 选择串口号，设置波特率 115200
3. 协议选择「FireWater」或「JustFloat」
4. 在单片机代码中按协议格式发送数据：
   ```c
   // 发送左右轮速度、目标速度、PID 输出
   printf("%d,%d,%d,%d\n", l_target, l_actual, r_target, r_actual);
   ```

**速度环阶跃响应测试：**
```c
// 在 main.c 中临时添加测试代码
if (test_mode) {
    l_speed_target = 30;  // 左轮给 30
    r_speed_target = 50;  // 右轮给 50
    delay_ms(2000);       // 持续 2 秒
    l_speed_target = 50;  // 切换
    r_speed_target = 30;
    delay_ms(2000);
}
```

**观察指标：**
- **上升时间**：速度从 0 到目标值的时间（理想 <200ms）
- **超调量**：是否超过目标值（理想 <10%）
- **稳态误差**：稳定后与目标值的偏差（理想 <2）
- **振荡**：是否反复震荡（Kp 过大或 Kd 不足）

**PID 参数调整策略：**
1. **Kp 偏小**：上升慢，到不了目标值 → 加大 Kp
2. **Kp 过大**：震荡、超调严重 → 减小 Kp
3. **Ki 不足**：有稳态误差（速度稳定在 28 而非 30）→ 加大 Ki
4. **Ki 过大**：启动时猛冲、低频振荡 → 减小 Ki
5. **Kd 作用**：平滑响应曲线，但编码器噪声大时会放大噪声

**脉冲观测：**
```c
// 打印编码器脉冲和目标脉冲
printf("%d,%d\n", l_encoder_count, l_target_count);
```
通过 Vofa+ 观察两条曲线的跟随效果：
- 曲线重合良好 → PID 参数合适
- 目标曲线陡峭而实际曲线缓慢 → Kp 不足
- 实际曲线震荡 → Kp 过大或 Kd 不足

#### 其他调试工具
- **OLED 显示**：当前速度、状态机状态、编码器读数
- **虚拟示波器**：通过逐飞上位机查看摄像头图像与扫线结果

## 📊 算法详解

### 1. 视觉系统参数调优

#### MT9V03X 摄像头关键参数

**增益（Gain）调节：**
```c
// 在 mt9v03x.c 中配置
MT9V03X_AGC_AEC_ENABLE = 0;  // 关闭自动增益/曝光
MT9V03X_GAIN = 32;           // 手动增益（范围：16-64）
```
- **Gain = 16-24**：低增益，适合强光环境（室外、顶灯直射）
- **Gain = 32-40**：中等增益，适合室内正常光照（推荐）
- **Gain = 48-64**：高增益，适合弱光环境，但噪声增大

**调节策略：**
1. 先在逐飞上位机查看实时图像
2. 如果图像过暗（黑线和地面都看不清）→ 增大 Gain
3. 如果图像过曝（大面积发白）→ 减小 Gain
4. 目标：黑线清晰可见，地面略灰但不发白

**曝光时间（Exposure Time）调节：**
```c
MT9V03X_EXPOSURE_TIME = 500;  // 曝光时间（范围：1-1000）
```
- **Time < 300**：短曝光，适合高速运动（图像更清晰但更暗）
- **Time = 400-600**：中等曝光（推荐）
- **Time > 700**：长曝光，适合低速/弱光（但高速时会模糊）

**调节策略：**
- 车速 > 2m/s：降低曝光时间至 300-400，减少运动模糊
- 车速 < 1.5m/s：可适当提高至 500-600，增强图像亮度
- 与 Gain 配合使用：优先调 Gain，Gain 到极限再调曝光

**帧率（Frame Rate）设置：**
```c
MT9V03X_FPS = 50;  // 帧率 50fps（可选：30/50/75/100）
```
- **30fps**：图像处理时间充裕（33ms/帧），但高速时响应慢
- **50fps**：均衡选择（20ms/帧），适合 1.5-2.5m/s 车速（推荐）
- **75fps**：高速响应（13ms/帧），但图像处理压力大
- **100fps**：极限帧率（10ms/帧），需要优化算法耗时

**本项目配置：**
- 帧率：50fps（图像周期 20ms，实际处理时间 200-700μs）
- 增益：32（室内正常光照）
- 曝光：500（中等曝光）

**图像处理时间分析：**
```
实测耗时：200-700μs（平均 450μs）
目标耗时：<2ms（留出余量给其他任务）
空帧处理：0.047ms（无图像数据时快速退出）
```

**耗时波动原因：**
1. **CPU 缓存命中率**：首次处理某行图像时缓存未命中，后续处理加速
2. **图像复杂度**：赛道笔直时处理快，多拐点时处理慢
3. **中断抢占**：编码器中断、串口中断可能打断图像处理

**优化策略：**
- 关闭不必要的中断（如调试串口的接收中断）
- 使用 DMA 传输图像数据，减少 CPU 参与
- 核心算法循环展开，减少分支预测失败

#### 摄像头安装角度
- **俯仰角**：15-25°（太平视野近但看不到远处，太俯冲看得远但近处畸变）
- **高度**：15-20cm（离地高度，视赛道宽度调整）
- **镜头清洁**：定期擦拭，指纹和灰尘严重影响对比度

### 2. 分区大津法（三区自适应阈值）

将图像分为上、中、下三个区域，分别计算大津阈值，解决赛道光照不均问题（如顶部强光、底部阴影）。

**算法原理：**
```c
// 远区（图像上 1/3）：降低阈值，防止远处丢线
threshold_far = otsu_threshold - 2;

// 中区（图像中 1/3）：标准阈值
threshold_mid = otsu_threshold - 1;

// 近区（图像下 1/3）：提高阈值，过滤近处噪声
threshold_near = otsu_threshold + 1;
```

**配合 Gamma 校正（γ=0.5）：**
- 压缩高亮区域，拉伸暗部对比度
- 使反光区域不过曝，阴影区域细节可见
- 在阈值二值化前进行，提升鲁棒性

### 3. 三向扫描提取中线

- **正向扫描**（从图像底部向上）：提取主赛道中线
- **左右扫描**：检测边界，辅助拐点判断
- **填充断线**：当中线断裂时，用历史数据三次样条插值补全

### 4. 拐点检测与验证

1. **粗检测**：列坐标跳变超过阈值 → 标记为疑似拐点
2. **筛选**：多拐点时保留最明显的（跳变幅度最大）
3. **矩形框验证**：在拐点周围画框，检查框内黑白像素比例，确认真实性

### 5. 状态机与偏置

- 状态机根据拐点类型（左拐/右拐/直行）查表，动态调整中线偏置
- 偏置值输出给 PID，实现预瞄控制（提前转向）
