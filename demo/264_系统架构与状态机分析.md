## 2. 图像处理管线详解

### 2.1 管线总览

每帧图像从摄像头到输出偏差值，经过 6 个阶段：

```
摄像头帧完成中断
    │
    ▼ (mt9v03x_finish_flag_1 = 1)
┌─────────────────────────────────────┐
│ ① image_scale()        ~0.3ms      │  188×120 → 156×60
│    最近邻采样，逐像素复制              │  最近邻插值
├─────────────────────────────────────┤
│ ② image_binarize()     ~1.5ms      │  分区大津法二值化
│    每20帧更新阈值(3区独立)            │  输出: bin_image[60][156]
├─────────────────────────────────────┤
│ ③ search_line()        ~0.5ms      │  逐行扫描边界
│    左边界 + 右边界 + 中线             │  输出: l_border/r_border/mid_line
├─────────────────────────────────────┤
│ ④ node_proc()          ~0.8ms      │  状态机处理节点
│    拐点检测 + 矩形框 + 转向决策        │  输出: turn_dir, node_state
├─────────────────────────────────────┤
│ ⑤ calc_image_error()   ~0.1ms      │  计算偏差
│    中线与图像中心的均值偏差            │  输出: image_err (float)
├─────────────────────────────────────┤
│ ⑥ draw_rect()          ~2.0ms      │  IPS114 SPI画矩形框
│    4条线段绘制                       │  ← 最耗时！SPI传输瓶颈
└─────────────────────────────────────┘
    │
    ▼
总耗时 ≈ 5ms (实测 T=778197 ticks @ 156MHz STM)
```

### 2.2 各阶段详细分析

#### ① image_scale() — 图像缩放

**输入**: `mt9v03x_image_1[120][188]` (原始灰度图)  
**输出**: `orig_image[60][156]` (缩放后灰度图)  
**算法**: 最近邻采样

```c
// 核心逻辑：行列分别做整数除法映射
src_row = row * 120 / 60;   // 行映射：2倍下采样
src_col = col * 188 / 156;  // 列映射：约1.2倍下采样
```

**性能分析**:
- 总像素: 60 × 156 = 9,360 次内存读写
- 每像素: 2次整数除法 + 2次乘法 + 2次数组索引
- TC264@156MHz: 约 0.3ms

**问题**: 使用整数除法(`row * 120 / 60`)，编译器无法优化为位移操作。可预计算查找表。

#### ② image_binarize() — 分区大津法二值化

**输入**: `orig_image[60][156]`  
**输出**: `bin_image[60][156]` (0=黑, 255=白)  
**算法**: 三区独立大津法 + 阈值限幅

```c
// 三区分区
BLOCK_FAR:   row 0~19   (远端，受反光影响最大)
BLOCK_MID:   row 20~39  (中间，弯道区域)
BLOCK_NEAR:  row 40~59  (近端，赛道入口)

// 阈值更新频率：每20帧更新一次
// 阈值范围限制：[THRESH_MIN=80, THRESH_MAX=200]
```

**大津法流程**:
1. 统计灰度直方图 (256 bin)
2. 遍历 256 个阈值，计算类间方差
3. 选择使方差最大的阈值

**性能分析**:
- 直方图统计: 9,360 次查表 + 加法
- 大津法遍历: 最多 256 次迭代 × 累积计算
- 二值化: 9,360 次比较
- 每20帧才跑一次完整大津法，其余帧只做二值化
- 平均耗时: ~1.5ms

#### ③ search_line() — 扫线

**输入**: `bin_image[60][156]`  
**输出**: `l_border[60]`, `r_border[60]`, `mid_line[60]`

```c
// 扫描方向：从底部(row=59)向顶部(row=0)
// 左边界：从左向右扫描，找 BLACK→WHITE 跳变
// 右边界：从右向左扫描，找 BLACK→WHITE 跳变
// 中线：(左边界 + 右边界) / 2
```

**性能分析**:
- 最坏情况: 每行扫描 156 像素 × 60 行
- 实际: 大部分行在前几个像素就找到边界
- 耗时: ~0.5ms

#### ④ node_proc() — 状态机 (详见第3章)

**输入**: `l_border[60]`, `r_border[60]`, `bin_image[60][156]`  
**输出**: `node_state`, `turn_dir`, `image_err`

#### ⑤ calc_image_error() — 偏差计算

**输入**: `mid_line[60]`  
**输出**: `image_err` (float, 范围 [-50, 50])

```c
// 只取近端行 (row 0~39)，排除底部 20 行
err = sum(mid_line[i] - COL/2) / (ROW - 20)
// 硬限幅: [-50, +50]
```

**问题**: 未启用滤波代码(被注释掉)，误差突变会直接传给PID。

#### ⑥ draw_rect() — 画框 (性能瓶颈!)

**输入**: `RECT_LEFT/RIGHT/TOP/BOTTOM` 常量  
**输出**: IPS114 屏幕上的红色矩形框

```c
ips114_draw_line(RECT_LEFT, RECT_TOP, RECT_RIGHT, RECT_TOP, RED);  // 上边
ips114_draw_line(RECT_LEFT, RECT_TOP, RECT_LEFT, RECT_BOTTOM, RED); // 左边
ips114_draw_line(RECT_RIGHT, RECT_TOP, RECT_RIGHT, RECT_BOTTOM, RED); // 右边
ips114_draw_line(RECT_LEFT, RECT_BOTTOM, RECT_RIGHT, RECT_BOTTOM, RED); // 下边
```

**⚠️ 这是管线中最大的性能瓶颈**:
- 每条线段通过 SPI 逐像素传输
- 4条线段总像素: (150-2)×2 + (58-1)×2 = 296 + 114 = 410 像素
- SPI @ ~30MHz: 每像素约 0.5μs → 410 × 0.5 = 205μs
- 但 IPS114 的 SPI 驱动有额外开销，实际约 2ms

## 3. 状态机完整分析

### 3.1 状态枚举定义

```c
typedef enum {
    NODE_NONE = 0,   // 无节点：正常巡线
    PRE_NODE,         // 预检测：远端发现弯道，提前准备
    NODE_DETECTED,    // 已检测：确认节点，锁定转向参数
    NODE_TURNING      // 执行中：正在转弯
} NodeState;
```

### 3.2 状态转换图

```
                    ┌─────────────────────────────────┐
                    │         NODE_NONE                │
                    │  正常巡线状态                     │
                    │  - find_guaidian(57, 5)          │
                    │  - 扫描远端row5→近端row57          │
                    └──────────┬───────────────────────┘
                               │
              发现拐点(row<=30) │ 发现拐点(row>30)
                    ┌──────────┴──────────┐
                    ▼                     ▼
          ┌──────────────────┐   ┌──────────────────┐
          │    PRE_NODE      │   │  NODE_DETECTED   │
          │  预检测状态       │   │  确认状态         │
          │  - find_guaidian │   │  - 锁定yaw_target│
          │    (57, 20)      │   │  - 记录yaw_before│
          │  - 等待拐点靠近   │   │  - → NODE_TURNING│
          └────────┬─────────┘   └──────────────────┘
                   │                      │
      拐点到近端    │                      │
      (row>30)     │                      │
                   ▼                      │
          ┌──────────────────┐            │
          │  NODE_DETECTED   │◄───────────┘
          └────────┬─────────┘
                   │
                   ▼
          ┌──────────────────┐
          │  NODE_TURNING    │
          │  执行转弯         │
          │  ┌─ GO_STRAIGHT  │
          │  ├─ TURN_LEFT    │
          │  └─ TURN_RIGHT   │
          │                  │
          │  校验完成后       │
          │  → NODE_NONE     │
          └──────────────────┘

  误检回退: PRE_NODE → NODE_NONE (拐点消失时)
```

### 3.3 各状态详细分析

#### NODE_NONE — 正常巡线状态

**触发条件**: 初始化 / 转弯完成后 / PRE_NODE 误检回退  
**执行内容**:

```c
case NODE_NONE:
    // 1. 远端前瞻扫描
    find_guaidian(ROW - 3, 5);  // row 57→5

    // 2. 如果发现拐点
    if (l_guaidian != 0 || r_guaidian != 0)
    {
        // 3. 矩形框检测（T字/十字确认）
        uint8 path_count = find_rect_path(bin_image);

        // 4. 判断转向类型
        if (path_count == 2)      turn_dir = corner_turn();   // 直角弯
        else if (path_count >= 3) turn_dir = plan_turn();     // T字/十字

        // 5. 根据拐点位置决定进入哪个状态
        if (l_guaidian <= 30 || r_guaidian <= 30)
            node_state = PRE_NODE;      // 远端 → 预准备
        else
            node_state = NODE_DETECTED; // 近端 → 直接执行
    }
    break;
```

**find_guaidian() 拐点检测逻辑**:

```c
// 扫描方向：从 start 到 end（从近到远）
// 检测条件：相邻5行的边界差值 >= 50 像素
for (i = start; i >= end; i--) {
    if (abs(l_border[i] - l_border[i - 5]) >= 50)
        l_guaidian = i;  // 记录第一个满足条件的行号
}
```

**find_rect_path() 矩形框检测**:

```
矩形区域定义:
  RECT_LEFT=2, RECT_RIGHT=150
  RECT_TOP=1,  RECT_BOTTOM=58

检测逻辑：在矩形4条边上找黑→白→白跳变
  上边: row=2, col 3→148
  下边: row=57, col 3→148
  左边: col=3, row 2→55
  右边: col=149, row 2→55
```

**corner_turn() 直角弯判断**:
```
下方有路 + 左边有路 + 右边无路 → TURN_LEFT
下方有路 + 右边有路 + 左边无路 → TURN_RIGHT
```

**plan_turn() 路径规划**:
```
使用预设 path[] 数组，按 node_count 顺序执行
path 数组由 PATH_SELECT 宏选择不同赛道
如果规划方向在图像中检测不到对应路径 → plan_warn_flag = 1
```

#### PRE_NODE — 预检测状态 (新增)

**触发条件**: NODE_NONE 中发现远端拐点 (row ≤ 30)  
**设计意图**: 在拐点还在远处时就开始准备，给小车更多反应时间

```c
case PRE_NODE:
    // 持续跟踪拐点位置
    find_guaidian(ROW - 3, 20);

    if (拐点存在) {
        if (拐点已到近端 row > 30)
            → NODE_DETECTED;  // 升级为正式检测
    } else {
        → NODE_NONE;          // 误检回退
        turn_dir = TURN_NONE;
    }
    break;
```

**⚠️ 当前问题**: PRE_NODE 状态下**没有执行任何控制动作**——既没有减速，也没有提前打方向。这使得 PRE_NODE 退化成了一个"等待状态"，浪费了提前检测的优势。

#### NODE_DETECTED — 确认状态

**触发条件**: 拐点在近端 (row > 30) / PRE_NODE 升级  
**执行内容**: 一次性锁定转向参数

```c
case NODE_DETECTED:
    if (!yaw_locked) {
        // 锁定目标偏航角
        if (turn_dir == TURN_LEFT)  std_yaw -= 90.0f;
        if (turn_dir == TURN_RIGHT) std_yaw += 90.0f;
        if (turn_dir == GO_STRAIGHT) yaw_target = std_yaw;

        yaw_before_turn = yaw_total;  // 记录转弯前偏航角
        yaw_locked = 1;
        node_state = NODE_TURNING;     // 立即进入执行
    }
    break;
```

**⚠️ 问题**: 这个状态只执行一次（通过 `yaw_locked` 保护），然后立即跳到 NODE_TURNING。**没有任何"减速"或"准备"动作**。

#### NODE_TURNING — 执行转弯状态

**三种转弯模式**:

```
┌─────────────────────────────────────────────────────────┐
│ GO_STRAIGHT（直行穿越）                                   │
│                                                          │
│  1. 记录起始距离 start_dist                               │
│  2. 持续直行直到 total_dist - start_dist > 0.25m         │
│  3. 检查路径数是否减少到 < 3（离开节点区域）               │
│  4. 校验实际 yaw 变化量判断真实方向                        │
│  5. 匹配 → turn_verify_flag=1, 不匹配 → =2             │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│ TURN_LEFT（左转）                                        │
│                                                          │
│  1. bias_left(): 将中线偏置到左侧 (change_line)          │
│  2. 持续偏置直到 yaw_total <= yaw_target + 20°           │
│  3. 校验实际转向方向                                      │
│  4. node_reset_state() → NODE_NONE                      │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│ TURN_RIGHT（右转）                                       │
│                                                          │
│  1. bias_right(): 将中线偏置到右侧 (change_line)         │
│  2. 持续偏置直到 yaw_total >= yaw_target - 20°           │
│  3. 校验实际转向方向                                      │
│  4. node_reset_state() → NODE_NONE                      │
└─────────────────────────────────────────────────────────┘
```

**bias_left() 偏置逻辑**:

```c
// 方式1: 拐点存在时 → 从拐点位置偏置到图像边缘
change_line(0, guaidian_row, 0, 0);

// 方式2: 拐点消失时 → 用赛道下边界替代
uint8 tb = find_line_bottom(0, bin_image);
change_line(0, tb, 0, 0);
```

**change_line() 补线函数**:
```c
// 在 y1~y2 范围内，用直线连接 (x1,y1) 和 (x2,y2)
// 结果写入 mid_line[]、l_border[]、r_border[]
// 相当于临时用一条斜线替代原来的中线
```

### 3.4 状态机时序分析（高速过弯场景）

```
时间轴 →
帧N:   [摄像头拍摄] → [处理5ms] → NODE_NONE: 扫到远端row25有拐点
                                         → find_rect_path: 确认直角弯
                                         → PRE_NODE

帧N+1: [摄像头拍摄] → [处理5ms] → PRE_NODE: 拐点还在row28
                                    (等待中，无任何控制动作)

帧N+2: [摄像头拍摄] → [处理5ms] → PRE_NODE: 拐点到row32
                                    → NODE_DETECTED: 锁定yaw
                                    → 立即进入NODE_TURNING

帧N+3: [摄像头拍摄] → [处理5ms] → NODE_TURNING: bias_left/right
                                    (此时车已经到弯道口了！)
```

**关键延迟分析**:
- 每帧间隔: ~10ms (100FPS设定，实际59FPS → ~17ms)
- 从 PRE_NODE 到 NODE_TURNING: 至少 1-2 帧 = 17~34ms
- 车速 2m/s 时: 17ms ≈ 3.4cm，34ms ≈ 6.8cm
- 这段时间内小车**没有任何转向动作**，完全靠直行惯性冲过弯道

## 4. 控制系统分析

### 4.1 控制架构

```
                    ┌──────────────┐
                    │ image_err    │
                    │ (图像偏差)    │
                    └──────┬───────┘
                           │
                    ┌──────▼───────┐     ┌──────────────┐
                    │ steer_pid    │◄────│ imu660rb_    │
                    │ _calc()      │     │ gyro_z       │
                    │              │     │ (陀螺仪Z轴)   │
                    │ P + 非线性P  │     └──────────────┘
                    │ + D - 陀螺补偿│
                    └──────┬───────┘

                           │
                    ┌──────▼───────┐
                    │ 限幅 ±6000   │
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              ▼                         ▼
     l_speed = base + steer    r_speed = base - steer
              │                         │
              ▼                         ▼
         motor_proc()             motor_proc()
         PWM + GPIO方向           PWM + GPIO方向
```

### 4.2 舵机PID公式

```c
steer_value = kp * error                    // P项：线性比例
            + kp2 * error * |error|         // 非线性P项：大误差时增强响应
            + kd * (error - last_error)     // D项：微分抑制振荡
            - (gyro_z * gkd) / 100          // 陀螺仪补偿：抑制车身旋转
```

**当前参数**:
| 参数 | 值 | 作用 |
|------|-----|------|
| kp | 95 | 线性比例系数 |
| kp2 | 0.009 | 非线性比例（大弯道加速响应） |
| kd | 0.2 | 微分系数 |
| gkd | 50 | 陀螺仪补偿系数 |

**非线性P项分析**:
- error=10时: kp2 * 10 * 10 = 0.9 (很小)
- error=30时: kp2 * 30 * 30 = 8.1 (开始显著)
- error=50时: kp2 * 50 * 50 = 22.5 (显著增强大弯道响应)

### 5.2 时序冲突分析

```
时间轴 (ms):
```
