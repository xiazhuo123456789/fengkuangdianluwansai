## 2. 摄像头传感器原理

### 2.1 CMOS 图像传感器工作流程

```
光子 → 微透镜 → 滤色片 → 光电二极管 → 电荷积累 → 模拟放大 → ADC → 数字像素值
                    ↑                    ↑           ↑         ↑
                 Bayer阵列          曝光时间控制   增益控制   12-bit→8-bit
```

每个像素的灰度值取决于三个因素：

```
灰度值 = f(光照强度 × 曝光时间 × 增益)
```

- **光照强度**：由环境光和被摄物体的反射率决定（你无法直接控制）
- **曝光时间**：传感器收集光子的时间长度（你可以控制）
- **增益**：电信号的放大倍数（你可以控制）

### 2.2 灰度值范围

```
0 ─────────────────────────────────────────────── 255
黑                                                    白
无光子                                              饱和
```

| 灰度范围 | 含义 | 图像表现 |
|----------|------|---------|
| 0~30 | 极暗，几乎无信号 | 全黑，噪点严重 |
| 30~80 | 暗区 | 能看到轮廓，细节模糊 |
| 80~160 | 中间灰度 | 正常曝光的背景区域 |
| 160~220 | 亮区 | 白线、亮色物体（**理想工作区**） |
| 220~255 | 过曝 | 信息丢失，白色饱和（**应避免**） |

## 3. 曝光时间详解

### 3.1 什么是曝光时间

曝光时间（Exposure Time）是传感器**光电二极管积累电荷的时间长度**。类比相机的快门速度：

```
曝光时间短 → 收集光子少 → 图像暗 → 运动模糊小
曝光时间长 → 收集光子多 → 图像亮 → 运动模糊大
```

### 3.2 MT9V03X 曝光时间参数

| 参数名 | 宏定义 | 当前值 | 有效范围 |
|--------|--------|--------|---------|
| 手动曝光时间 | `CAMERA_EXPOSURE` | 800 | 0~800（0=自动） |
| 实际曝光时间 | `MT9V03X_1_EXP_TIME_DEF` | 512 | 1~800 |

**单位换算**：

```
1 个曝光单位 ≈ 6.9 微秒（μs）

CAMERA_EXPOSURE = 500  →  500 × 6.9μs = 3.45 ms
CAMERA_EXPOSURE = 800  →  800 × 6.9μs = 5.52 ms
```

### 3.3 调高曝光时间的效果

```
曝光时间 ↑ → 图像整体变亮
           → 暗区细节增加（白线更容易看清）
           → 亮区可能过曝（灰度值冲到 255）
           → 运动模糊增大（车速快时白线拖影）
           → 帧率可能下降（曝光时间不能超过帧间隔）
```

### 3.4 调低曝光时间的效果

```
曝光时间 ↓ → 图像整体变暗
           → 亮区细节保持（白线不会过曝）
           → 暗区丢失（白线可能看不见）
           → 运动模糊减小（白线边缘锐利）
           → 帧率可以更高
```

### 3.5 曝光时间与帧率的关系

```
帧间隔 = 1000ms ÷ FPS

100 FPS → 帧间隔 = 10ms → 最大曝光时间 < 10ms（约 1400 单位）
 50 FPS → 帧间隔 = 20ms → 最大曝光时间 < 20ms（约 2800 单位）
 30 FPS → 帧间隔 = 33ms → 最大曝光时间 < 33ms（约 4700 单位）
```

> **重要约束**：曝光时间必须小于帧间隔。如果曝光时间 > 帧间隔，摄像头来不及完成曝光就被下一帧打断，导致画面异常。

| FPS | 帧间隔 | 最大曝光单位 | 最大曝光时间 |
|-----|--------|------------|------------|
| 100 | 10ms | ~1400 | ~9.7ms |
| 80 | 12.5ms | ~1800 | ~12.4ms |
| 50 | 20ms | ~2800 | ~19.3ms |
| 30 | 33ms | ~4700 | ~32.4ms |

## 4. 模拟增益详解

### 4.1 什么是增益

增益（Gain）是对光电二极管输出的**电信号进行放大**的倍数。类比音响的音量旋钮——信号弱时加大音量，但噪声也会一起被放大。

### 4.2 MT9V03X 增益参数

| 参数名 | 宏定义 | 当前值 | 有效范围 |
|--------|--------|--------|---------|
| 模拟增益 | `CAMERA_GAIN` | 64 | 16~64 |
| 实际增益 | `MT9V03X_1_GAIN_DEF` | 32 | 16~64 |

**增益值与实际放大倍数的换算**：

```
实际增益 = 2^(GAIN / 16)

GAIN = 16  →  2^(16/16) = 2^1 = 2 倍   （最暗，噪声最小）
GAIN = 24  →  2^(24/16) = 2^1.5 ≈ 2.8 倍
GAIN = 32  →  2^(32/16) = 2^2 = 4 倍   （默认值）
GAIN = 40  →  2^(40/16) = 2^2.5 ≈ 5.7 倍
GAIN = 48  →  2^(48/16) = 2^3 = 8 倍
GAIN = 56  →  2^(56/16) = 2^3.5 ≈ 11.3 倍
GAIN = 64  →  2^(64/16) = 2^4 = 16 倍   （最亮，噪声最大）
```

> **注意**：这里的增益值不是线性的！从 32 到 48 是从 4 倍跳到 8 倍，不是"一点点"的增加。

### 4.3 调高增益的效果

```
增益 ↑ → 信号放大更多 → 图像整体变亮
       → 暗区被放大 → 能看到原本看不见的细节
       → 噪声也被放大 → 图像颗粒感明显（"雪花"）
       → 灰度分布被拉伸 → OTSU 阈值可能不准
       → 对比度下降（暗区亮了，亮区没变）
```

### 4.4 调低增益的效果

```
增益 ↓ → 信号放大减少 → 图像整体变暗
       → 噪声减小 → 图像干净
       → 暗区细节丢失
       → 对比度提高（黑白分界更清晰）
```

### 4.5 增益 vs 曝光时间：优先调哪个？

```
推荐顺序：先调增益，再调曝光时间

理由：
1. 增益影响噪声，曝光时间影响运动模糊
2. 低增益 + 长曝光 = 图像干净但有运动模糊
3. 高增益 + 短曝光 = 图像模糊但无运动模糊
4. 最佳组合：尽可能低的增益 + 足够的曝光时间
```

| 场景 | 推荐增益 | 推荐曝光 | 说明 |
|------|---------|---------|------|
| 强光户外 | 16~24 | 100~200 | 光线充足，不需要放大 |
| 室内正常灯光 | 24~32 | 300~500 | 平衡点 |
| 暗光+偏振片 | 40~48 | 500~700 | 需要放大，但噪声可接受 |
| 极暗环境 | 48~64 | 700~800 | 最大限度，噪声严重 |

## 5. 帧率详解

### 5.1 什么是帧率

帧率（FPS, Frames Per Second）= 每秒采集的图像帧数。

```
100 FPS → 每秒拍 100 张 → 每张间隔 10ms
 50 FPS → 每秒拍 50 张  → 每张间隔 20ms
 30 FPS → 每秒拍 30 张  → 每张间隔 33ms
```

### 5.2 帧率参数

| 参数名 | 宏定义 | 当前值 | 有效范围 |
|--------|--------|--------|---------|
| 帧率 | `CAMERA_FPS` | 100 | 20~100 |
| 摄像头1帧率 | `MT9V03X_1_FPS_DEF` | 100 | 20~100 |
| 摄像头2帧率 | `MT9V03X_2_FPS_DEF` | 50 | 20~100 |

> **注意**：`CAMERA_FPS` 和 `MT9V03X_1_FPS_DEF` 必须保持一致。改一个必须同时改另一个。

### 5.3 调高帧率的效果

```
帧率 ↑ → 每帧时间变短 → 运动模糊减小（白线边缘锐利）
       → 反应更快（PID 控制频率提高）
       → 曝光时间上限降低（帧间隔缩短）
       → 图像可能变暗（曝光时间被迫缩短）
       → 数据量增大（对 SPI 传输和 CPU 处理要求更高）
```

### 5.4 调低帧率的效果

```
帧率 ↓ → 每帧时间变长 → 运动模糊增大（车速快时拖影）
       → 反应变慢（PID 控制延迟增大）
       → 曝光时间上限提高（可以收集更多光子）
       → 图像可以更亮（暗光环境有利）
       → 数据量减小（CPU 负担减轻）
```

### 5.5 帧率与车速的关系

```
车速 = 1 m/s（3.6 km/h），画面宽度 0.3m
→ 每帧车移动 1cm → 轻微模糊，可接受

车速 = 2 m/s（7.2 km/h）
→ 每帧车移动 2cm → 明显模糊

车速 = 3 m/s（10.8 km/h）
→ 每帧车移动 3cm → 严重模糊，影响扫线精度

100 FPS 时：
  1 m/s → 每帧移动 1cm ✓
  2 m/s → 每帧移动 2cm ✓（可接受）
  3 m/s → 每帧移动 3cm △（勉强）

50 FPS 时：
  1 m/s → 每帧移动 2cm ✓
  2 m/s → 每帧移动 4cm ✗（模糊严重）
```

> **建议**：高速车（>2m/s）用 100 FPS，低速车（<1.5m/s）可以用 50 FPS 换取更长曝光时间。

## 6. 三大参数的相互关系

### 6.1 曝光三角

```
           曝光时间
              /\
             /  \
            /    \
           / 亮度  \
          /________\
    增益            帧率
```

三者共同决定图像亮度：

```
图像亮度 ∝ 曝光时间 × 增益 × 环境光照

要保持亮度不变：
  曝光时间减半 → 增益需要加倍（GAIN +16）
  帧率加倍     → 曝光时间减半 → 增益需要加倍
```

### 6.2 参数调节优先级

```
第一优先：增益（影响噪声，尽量低）
    ↓
第二优先：曝光时间（在帧间隔允许范围内尽量长）
    ↓
第三优先：帧率（根据车速决定）
```

### 6.3 具体场景参数对照

| 场景 | FPS | 增益 | 曝光 | 预期最大灰度 | 预期帧间隔 |
|------|-----|------|------|------------|----------|
| 强光户外 | 100 | 16 | 100 | 180~210 | 10ms |
| 日光灯室内 | 100 | 24 | 300 | 170~200 | 10ms |
| 暗光室内 | 100 | 32 | 500 | 150~190 | 10ms |
| 暗光+偏振片 | 80 | 40 | 600 | 140~180 | 12.5ms |
| 暗光+偏振片+补光 | 100 | 32 | 400 | 160~200 | 10ms |
| 极暗无偏振片 | 60 | 48 | 700 | 130~170 | 16.7ms |
| 极暗+偏振片 | 50 | 56 | 800 | 120~160 | 20ms |

## 7. 灰度值监控调参法

### 7.1 核心原理

**通过监控每帧图像的最大灰度值来判断曝光是否合适。**

```
最大灰度值 < 200  →  曝光合适，黑白分明
最大灰度值 ≥ 255  →  曝光过强，白色饱和，阈值计算困难
```

### 7.2 为什么最大灰度值很重要

```
理想情况（最大灰度 ≈ 180~200）：

灰度分布:
  ██
  ████
  ██████
  ████████
  ██████████
  ████████████
  ██████████████
  0    50   100  150  200  255
       ↑              ↑
     黑线峰值       白线峰值
     (阈值在这里自动计算准确)


过曝情况（最大灰度 = 255）：

灰度分布:
  ██
  ████
  ██████
  ████████████████████  ← 白线像素堆积在255
  ████████████████████
  ████████████████████
  0    50   100  150  200  255
       ↑              ↑
     黑线峰值     大量堆积在这里
                 (阈值被推向中间，不准确)
```

### 7.3 监控代码思路

在 `image_binarize()` 之前，扫描一帧图像找最大灰度值：

```c
// 思路（不改你的代码，仅说明原理）
uint8 max_gray = 0;
for (int i = 0; i < ROW; i++) {
    for (int j = 0; j < COL; j++) {
        if (orig_image[i][j] > max_gray) {
            max_gray = orig_image[i][j];
        }
    }
}
// max_gray 就是这帧图像的最大灰度值
// 通过串口/蓝牙发送到电脑监控
```

### 7.4 灰度值区间判断

| 最大灰度值 | 判断 | 操作 |
|-----------|------|------|
| < 100 | 严重欠曝 | 大幅增加曝光（+200）或增益（+16） |
| 100~140 | 轻微欠曝 | 适度增加曝光（+50~100） |
| 140~200 | **理想区间** | 保持不变 |
| 200~230 | 轻微过曝 | 适度减少曝光（-50~100） |
| 230~255 | 明显过曝 | 大幅减少曝光（-100~200） |
| 255（饱和） | 严重过曝 | 立即降低曝光/增益 |

### 7.5 调参口诀

```
最大灰度高了降曝光，低了加曝光。
先调增益定基调，再调曝光微调亮。
帧率根据车速选，暗光环境降帧率。
目标区间 150~200，黑白分明阈值准。
```

## 8. OTSU 分区大津法阈值分析

### 8.1 OTSU 原理

OTSU（大津法/最大类间方差法）自动寻找最佳二值化阈值，使黑白两类像素的**类间方差最大**。

```
对于每个可能的阈值 T (0~255)：
  计算：σ²(T) = ω₀(T) × ω₁(T) × [μ₀(T) - μ₁(T)]²
  
  ω₀ = 黑色像素比例
  ω₁ = 白色像素比例
  μ₀ = 黑色像素平均灰度
  μ₁ = 白色像素平均灰度

最佳阈值 T* = 使 σ²(T) 最大的 T
```

### 8.2 分区 OTSU 的优势

全图只算一个阈值的问题：如果图像上半部分很亮、下半部分很暗，统一阈值会导致**上半部分过白、下半部分过黑**。

分区 OTSU 把图像分成多个区域，每个区域独立计算阈值：

```
┌─────────────────────┐
│   远区 (0~19行)      │  → 阈值 thresh_far
│   可能较暗（远处）    │
├─────────────────────┤
│   中区 (20~39行)     │  → 阈值 thresh_mid
│   正常亮度            │
├─────────────────────┤
│   近区 (40~59行)     │  → 阈值 thresh_near
│   可能较亮（近处补光） │
└─────────────────────┘
```

### 8.3 项目中的 OTSU 参数

| 参数 | 当前值 | 含义 |
|------|--------|------|
| `THRESH_MIN` | 30 | 阈值下限（低于此值强制拉到此值） |
| `THRESH_MAX` | 230 | 阈值上限（高于此值强制拉到此值） |
| `THRESH_UPDATE_FRAMES` | 20 | 每 20 帧重新计算一次阈值 |
| `BLOCK_FAR_START/END` | 0/20 | 远区范围 |
| `BLOCK_MID_START/END` | 20/40 | 中区范围 |
| `BLOCK_NEAR_START/END` | 40/60 | 近区范围 |

### 8.4 THRESH_MIN 的影响

```
THRESH_MIN 太大（如 150）：
  → 暗光环境下 OTSU 算出阈值可能是 80
  → 被强制拉到 150
  → 150 以上的灰度全被判为白色
  → 黑线中较亮的部分也被判为白色
  → 白线变窄甚至消失 ✗

THRESH_MIN 太小（如 10）：
  → 几乎不限制
  → 可能算出极低阈值（如 20）
  → 20 以上全是白色
  → 噪声也被判为白色 ✗
```

### 8.5 THRESH_MAX 的影响

```
THRESH_MAX 太小（如 150）：
  → 暗光环境下可能不需要限制
  → 但强光下白线灰度 255，OTSU 可能算出 180
  → 被限制在 150
  → 反而合理 ✗
  → 暗光下 OTSU 算出 160，被限制在 150
  → 白线部分丢失 ✗

THRESH_MAX 太大（如 250）：
  → 过曝时 OTSU 算出 230+
  → 不限制，阈值偏高
  → 黑线中较暗的也被判为黑色
  → 白线变宽 ✗
```

### 8.6 THRESH_UPDATE_FRAMES 的影响

```
THRESH_UPDATE_FRAMES = 1（每帧更新）：
  → 阈值随每帧变化 → 跟踪光照变化快
  → 但阈值抖动 → 二值化结果不稳定 → 边界线跳动

THRESH_UPDATE_FRAMES = 20（每20帧更新）：
  → 100FPS 时 = 200ms 更新一次
  → 阈值稳定 → 二值化结果稳定
  → 光照突变时反应慢（200ms 才适应）

THRESH_UPDATE_FRAMES = 50（每50帧更新）：
  → 100FPS 时 = 500ms 更新一次
  → 阈值非常稳定
  → 进出隧道等光照突变场景可能跟不上
```

## 9. 偏振片对参数的影响

### 9.1 偏振片的光损

偏振片会过滤掉一个偏振方向的光，理论光损 **50%**（1 档），实际加上玻璃/塑料基板的吸收，光损约 **60%~75%**（1~2 档）。

```
无偏振片：100% 光量
加偏振片：25%~40% 光量

相当于降低 1~2 档曝光
```

### 9.2 加偏振片后的参数补偿

| 参数 | 无偏振片 | 加偏振片（补偿后） | 说明 |
|------|---------|------------------|------|
| 曝光时间 | 300 | 500~700 | 需要 1.5~2 倍补偿 |
| 增益 | 32 | 40~48 | 增大 1~2 档 |
| 最大灰度 | 180 | 保持 150~200 | 目标不变 |

### 9.3 偏振片角度调整技巧

偏振片不是随便装上去就行的，需要**旋转到合适角度**：

```
目标：让地面的镜面反射光（水平偏振）被挡住
      同时让白线的漫反射光（各方向）尽量通过

步骤：
1. 不装偏振片，找到反光最严重的位置
2. 装上偏振片，对着反光位置慢慢旋转
3. 观察摄像头画面：反光消失时的角度就是正确角度
4. 固定偏振片在该角度
```

## 10. TC264D MCU 算力分析

### 10.1 核心性能

| 指标 | 值 | 说明 |
|------|-----|------|
| 主频 | 200 MHz | 每秒 2 亿条指令 |
| 单精度浮点 | 支持 | 硬件 FPU，PID 浮点运算不耗时 |
| DSP 指令 | 支持 | 单周期乘加，适合图像卷积 |
| DMA 通道 | 8 | 摄像头数据搬运不占 CPU |
| SRAM | 480 KB | 存双目图像（188×120×2×2 = 90KB）绑绑有余 |

### 10.2 各任务耗时估算

```
单条指令 ≈ 5ns（200MHz）

任务                        估算耗时        占 10ms 帧预算
────────────────────────────────────────────────────────
图像缩放 (188×120→156×60)    ~0.5ms         5%
二值化 (156×60)              ~0.3ms         3%
分区 OTSU (3区×60行×156列)   ~0.8ms         8%
扫线 (60行×156列)            ~0.4ms         4%
拐点检测                     ~0.1ms         1%
矩形框检测                   ~0.2ms         2%
节点状态机                   ~0.1ms         1%
PID 控制 (中断中)            ~0.05ms        0.5%
IPS114 显示                  ~2~5ms         20~50%
────────────────────────────────────────────────────────
总计                         ~5~8ms         50~80%
```

> **结论**：TC264D 的算力对本项目绰绰有余。瓶颈不在 CPU，而在**摄像头数据传输**和 **SPI 显示**。CPU 有大量空闲时间可以用于更复杂的算法。

### 10.3 双核利用

```
CPU0（当前使用）：
  ├── 主循环：图像处理 + 显示
  └── CCU60_CH1 中断：PID 控制 + 按键

CPU1（当前空闲）：
  └── 可用于：图像预处理、通信、复杂算法
```

### 11.1 第一步：建立基准

```c
#define THRESH_MAX         220
```

### 11.2 第二步：监控最大灰度

把图像通过蓝牙/无线串口传到电脑，用上位机（逐飞助手）查看：
- 每帧的最大灰度值
- 灰度直方图
- 二值化效果

### 11.3 第三步：逐步调整

```
if (最大灰度 < 140) {
    // 欠曝 → 加曝光
    CAMERA_EXPOSURE += 50;  // 每次加 50
} else if (最大灰度 > 210) {
    // 过曝 → 降曝光
    CAMERA_EXPOSURE -= 50;  // 每次减 50
} else {
    // 在 140~210 之间 → 合适，停止调整
}
```

### 11.4 第四步：固定最优值

找到合适的曝光后，**固定不再动**，然后只调 PID 参数。

## 12. 常见问题与解决方案

### 12.1 问题：图像全黑

```
原因：曝光时间太短 或 增益太低 或 环境光不足
解决：
  1. 检查 init.c 中曝光设置是否被注释
  2. 增大 CAMERA_EXPOSURE（每次 +100）
  3. 增大 CAMERA_GAIN（每次 +8）
  4. 如果还是黑 → 物理补光（LED 灯）
```

### 12.2 问题：图像全白/过曝

```
原因：曝光时间太长 或 增益太高 或 有强反光
解决：
  1. 降低 CAMERA_EXPOSURE（每次 -100）
  2. 降低 CAMERA_GAIN（每次 -8）
  3. 加偏振片抗反光
```

### 12.3 问题：白线模糊/拖影

```
原因：帧率太低，车速太快导致运动模糊
解决：
  1. 提高 FPS（100）
  2. 如果曝光时间太长导致帧率降 → 适当缩短曝光
  3. 牺牲亮度换取清晰度
```

### 12.4 问题：噪点严重/图像有雪花

```
原因：增益太高
解决：
  1. 降低 CAMERA_GAIN
  2. 增加 CAMERA_EXPOSURE 替代增益（用曝光补偿）
  3. 加补光灯减少对增益的依赖
```

### 12.5 问题：OTSU 阈值不稳定/跳动

```
原因：THRESH_UPDATE_FRAMES 太小
解决：
  1. 增大 THRESH_UPDATE_FRAMES（20~50）
  2. 检查光照是否稳定
```

### 12.6 问题：加偏振片后白线看不见

```
原因：偏振片光损太大 + 环境光本来就暗
解决：
  1. 增大曝光时间（+200~300）
  2. 增大增益（+8~16）
  3. 最有效：加补光灯（从车头照射赛道）
```

### 12.7 问题：白斑反光（不加偏振片时）

```
原因：地面镜面反射直接进入摄像头
解决：
  1. 加偏振片（角度调好）
  2. 软件过滤（连通域面积过滤）
  3. 降低增益减少过曝区域
```

## 13. 参数速查表

### 13.1 摄像头参数

| 参数 | 宏定义 | 范围 | 调高效果 | 调低效果 |
|------|--------|------|---------|---------|
| 曝光时间 | `CAMERA_EXPOSURE` | 0~800 | 图像变亮，可能过曝 | 图像变暗，可能欠曝 |
| 模拟增益 | `CAMERA_GAIN` | 16~64 | 图像变亮，噪声增加 | 图像变暗，噪声减小 |
| 帧率 | `CAMERA_FPS` | 20~100 | 模糊减小，曝光上限降 | 模糊增大，曝光上限升 |
| 自动曝光 | `AUTO_EXP_DEF` | 0~63 | 0=手动，非0=自动目标亮度 |

### 13.2 图像处理参数

| 参数 | 宏定义 | 范围 | 调高效果 | 调低效果 |
|------|--------|------|---------|---------|
| 阈值下限 | `THRESH_MIN` | 0~255 | 黑线变窄，可能丢失 | 噪声可能被判为白色 |
| 阈值上限 | `THRESH_MAX` | 0~255 | 白线变窄，可能丢失 | 过曝区域更明显 |
| 更新频率 | `THRESH_UPDATE_FRAMES` | 1~100 | 阈值更稳定，反应慢 | 阈值更灵敏，可能抖动 |

```
  0~ 80     严重欠曝    曝光+200 / 增益+16 / 补光

200~230     轻微过曝    曝光-50~100
```
