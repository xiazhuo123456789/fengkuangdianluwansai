# MT9V03x 摄像头：帧率、曝光时间、增益 详解

## 一、三个参数是什么

### 帧率（FPS）

帧率 = 摄像头每秒钟拍多少张照片。

| 帧率 | 每帧间隔 | 含义 |
|------|---------|------|
| 100 FPS | 10ms | 每秒拍100张，每张之间间隔10毫秒 |
| 50 FPS | 20ms | 每秒拍50张，每张之间间隔20毫秒 |
| 30 FPS | 33ms | 每秒拍30张，每张之间间隔33毫秒 |

打个比方：帧率就像你眨眼的频率。眨得快（高帧率）能及时看到东西，但每次眨眼时间短，进光少；眨得慢（低帧率）每次看得清楚，但容易错过快速变化的东西。

### 曝光时间

曝光时间 = 每张照片的"快门打开时间"，即传感器接收光线的时长。

- 曝光时间越长 → 画面越亮（进光多）
- 曝光时间越短 → 画面越暗（进光少）

MT9V03x 曝光时间单位 ≈ 6.9μs/格，寄存器为12位（理论范围 0~4095）。

### 增益（GAIN）

增益 = 电子信号放大倍数，把传感器收到的光信号放大。

| GAIN值 | 倍数 | 效果 |
|--------|------|------|
| 16 | 2倍 | 最暗，噪点最少 |
| 32 | 4倍 | 适中（默认值） |
| 48 | 16倍 | 较亮，噪点开始明显 |
| 64 | 64倍 | 最亮，噪点很多，画面发毛 |

增益不卡顿、不降帧，纯粹是亮度调节。但增益越高噪点越多，二值化时容易出现误判。

## 二、三者之间的关系

### 核心约束：曝光时间 ≤ 一帧总时间

```
一帧总时间 = 1000ms / 帧率
曝光时间不能超过一帧总时间，否则芯片自动降帧
```

### 互相影响方式

| 调整 | 对曝光的影响 | 对帧率的影响 | 对增益的影响 |
|------|-------------|-------------|-------------|
| **曝光拉大** | 画面变亮 | 若超过帧时间，帧率被迫降低 | 无 |
| **帧率拉高** | 每帧时间变短，曝光上限降低 | 画面更连贯 | 无 |
| **增益拉高** | 画面变亮（非光学手段） | 无 | 噪点增多 |

**简单记：曝光和帧率是"抢时间"的关系，增益是"补亮度"的。**

### 实际帧时间与曝光上限参考

| 帧率 | 一帧总时间 | 曝光上限（格） | 曝光上限（时间） |
|------|-----------|---------------|-----------------|
| 100 FPS | 10ms | ~1400 | ~10ms |
| 50 FPS | 20ms | ~2800 | ~20ms |
| 30 FPS | 33ms | ~4200 | ~33ms |

> 注意：以上曝光上限是理论值，实际还需预留读出时间，建议留 20%~30% 余量。

## 三、帧率设高了会怎样

### 帧率过高 → 每帧时间太短 → 曝光没空间

| FPS | 一帧时间 | 曝光还能用多少 |
|-----|---------|---------------|
| 100 | 10ms | 够用 |
| 200 | 5ms | 很紧，曝光稍微大一点就被迫降帧 |
| 500 | 2ms | 基本没法用，曝光几乎为0，画面全黑 |

### 帧率过高 → MCU处理不完 → 大量丢帧

```
时间线（500FPS，每帧2ms）：

摄像头：  |帧1|帧2|帧3|帧4|帧5|帧6|帧7|...
          0   2   4   6   8  10  12 ms

MCU处理： |==帧1处理==|还没算完...|帧4来了，帧2、3已经丢了
          0      5ms        ↑
                     帧2在2ms时就来了，但你还在算帧1
```

帧2、帧3 直接被跳过，你算的图其实是很多帧之前的，小车看到的是"过去"的路况，控制会不准。

### 结论

- **不要盲目追求高帧率**，MCU处理速度是瓶颈
- **100 FPS 是智能车的常用选择**，平衡了响应速度和处理时间
- 如果算法复杂（二值化+去噪+扫线+节点处理），50~100 FPS 更稳妥

## 四、曝光时间拉长后屏幕卡顿的原因

```
曝光拉长 → 超过当前帧率允许的时间 → 芯片自动降帧 → 刷新变慢 → 卡顿
```

例如：
- `CAMERA_FPS = 100`（10ms一帧）
- 曝光设到 2000（约14ms）
- 14ms > 10ms → 芯片被迫降到约 50FPS
- 屏幕刷新从100次/秒变成50次/秒 → 肉眼看到卡顿

**代码层面的原因**：`image_proc` 是一帧一处理的：

```c
if (mt9v03x_finish_flag_1)  // 等到新帧才处理
{
    mt9v03x_finish_flag_1 = 0;
    image_scale(...);
    image_binarize(...);
    image_denoise();
    search_line();
    ...
}
```

帧率从100降到30，显示刷新也从100次/秒降到30次/秒，看起来就像PPT。

## 五、调参建议

### 优先级

```
1. 先调帧率（确定响应速度）
2. 再调曝光（在该帧率下把亮度调对）
3. 最后调增益（曝光不够亮再用增益补）
```

### 推荐配置

| 环境 | 帧率 | 曝光 | 增益 | 说明 |
|------|------|------|------|------|
| 正常亮度 | 100 | 0（自动）或 100~200 | 32 | 默认配置 |
| 暗教室 | 50~100 | 300~500 | 32~48 | 帧率降低换更长曝光 |
| 全黑环境 | 30~50 | 500~800 | 48~64 | 最大曝光+高增益 |

### 调参口诀

> **亮度不够，先加曝光，再加帧率，最后加增益。**
> **增益尽量保持低值（16~32），别用增益硬拉亮度，噪点会毁掉二值化。**
