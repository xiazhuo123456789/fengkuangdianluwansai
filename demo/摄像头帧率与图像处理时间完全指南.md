## 1. 基本概念

### 1.1 帧率（FPS）是什么？

帧率 = **每秒摄像头输出的完整图像帧数**。

```
摄像头设置帧率 = 100 FPS
→ 每秒输出 100 张图片
→ 每张图片的间隔 = 1000ms / 100 = 10ms
→ 每张图片叫"一帧"
```

### 1.2 处理一帧图像是什么意思？

"处理一帧" = **CPU从内存中读取一张图片，完成所有算法计算，输出控制信号**。

```
一帧的完整生命周期：

摄像头硬件                     CPU软件
   │                            │
   ├─ 曝光采集 → DMA搬运到内存   │
   │                            ├─ 读取内存中的图像
   │                            ├─ 二值化（灰度→黑白）
   │                            ├─ 八邻域爬线（找边界）
   │                            ├─ 四方位丢失特征
   │                            ├─ 中线绘制
   │                            ├─ 路口判断 + 状态机
   │                            ├─ 误差计算
   │                            └─ PID → PWM → 电机
   │                            │
   ├─ 下一帧开始曝光 ───────────→│ ← CPU必须在下一帧到来前处理完
```

### 1.3 处理时间是什么意思？

处理时间 = **CPU处理一帧图像花了多少毫秒**。

```
处理时间 = 结束时间戳 - 开始时间戳

例如：
  开始时间戳 = 1,000,000 us（1秒时）
  结束时间戳 = 1,001,300 us（1.0013秒时）
  处理时间 = 1,300 us = 1.3 ms
```

### 1.4 三者的关系

```
┌──────────────────────────────────────────────────────┐
│  帧率（摄像头决定）     100 FPS                       │
│  ↓                                                   │
│  一帧时间 = 1000/100 = 10 ms                         │
│  ↓                                                   │
│  CPU处理一帧花了 3 ms  ← 这就是"处理时间"             │
│  ↓                                                   │
│  10 ms - 3 ms = 7 ms 空闲（CPU可以干别的）           │
│  ↓                                                   │
│  系统有效帧率 = 1000 / 10 = 100 FPS（正常）           │
└──────────────────────────────────────────────────────┘

如果处理时间 > 一帧时间（比如处理要 15ms，但帧间隔只有 10ms）：
  → CPU还没处理完，下一帧就到了 → 丢帧！
  → 系统有效帧率 = 1000 / 15 = 66 FPS（降帧）
```

## 2. 摄像头工作原理

### 2.1 关键信号

| 信号 | 作用 | 类比 |
|------|------|------|
| **VSYNC** | 一帧的开始/结束 | 相机快门"咔嚓"一下 |
| **PCLK** | 每个像素输出的时钟 | 打印机每吐一个点 |
| **D[7:0]** | 8位像素数据 | 当前像素的灰度值(0~255) |
| **DMA** | 硬件自动搬运数据 | 搬运工，CPU不用管 |

### 2.2 采集流程

```
VSYNC上升沿（新帧开始）
  ↓
摄像头逐行输出像素：
  Row 0: PCLK→PCLK→PCLK→... (188个脉冲 = 188列)
  Row 1: PCLK→PCLK→PCLK→...
  ...
  Row 119: PCLK→PCLK→PCLK→...
  ↓
每个PCLK脉冲触发DMA：
  DMA自动把D[7:0]的值写入内存 buffer[row][col]
  CPU完全不参与搬运
  ↓
DMA计数器归零 → DMA完成中断
  ↓
mt9v03x_finish_flag_1 = 1 → CPU可以开始处理了
```

### 2.3 一帧数据量

```
188 × 120 灰度图 = 22,560 字节 ≈ 22 KB
156 × 60 裁剪后  = 9,360 字节  ≈ 9 KB（你的项目用这个）
```

## 3. 帧率计算

### 3.1 MT9V03X 帧率公式

```
FPS = PCLK / (H_total × V_total)

PCLK = 像素时钟频率（约27MHz）
H_total = 有效列数 + 行消隐（约250列）
V_total = 有效行数 + 场消隐（约10行）
```

### 3.2 不同分辨率的理论帧率

| 分辨率 | H_total | V_total | 理论FPS | 实际FPS |
|--------|---------|---------|---------|---------|
| 752×480（全幅） | 1002 | 490 | 55 | 50~60 |
| 188×120 | 438 | 130 | 477 | 100~200 |
| 156×60（你的） | 406 | 70 | 944 | 100~200 |

**实际帧率远低于理论值，因为曝光时间限制了帧率上限。**

### 3.3 你的项目配置

```c
// zf_device_mt9v03x_double.h
#define MT9V03X_1_FPS_DEF   (100)   // 摄像头1：100 FPS
#define MT9V03X_1_EXP_TIME_DEF (512) // 曝光时间：512us
```

→ 摄像头输出 100 FPS，每帧间隔 10ms。

## 4. 图像处理流程与耗时

### 4.1 你的 image_proc() 处理链

```c
void image_proc(void)
{
    if (mt9v03x_finish_flag_1)           // 等一帧采集完
    {
        mt9v03x_finish_flag_1 = 0;

        image_scale(mt9v03x_image_1);     // ① 裁剪缩放 188×120 → 156×60
        image_binarize(orig_image);        // ② 分块OSTU二值化
        search_line_8();                   // ③ 八邻域爬线
        get_lost_feature();                // ④ 四方位丢失特征
        draw_midline();                    // ⑤ 中线绘制
        node_proc();                       // ⑥ 路口判断 + 状态机
        calc_image_error();                // ⑦ 误差计算
    }
}
```

### 4.2 各步骤估算耗时（TC264 @ 300MHz）

| 步骤 | 操作 | 像素访问次数 | 估算耗时 |
|------|------|-------------|---------|
| ① image_scale | 156×60次赋值 | 9,360 | ~0.05 ms |
| ② image_binarize | 156×60次比较 | 9,360 | ~0.05 ms |
| ③ search_line_8 | 最多240步×16邻居 | ~3,840 | ~0.2 ms |
| ④ get_lost_feature | 扫描3个丢失行/列 | ~600 | ~0.02 ms |
| ⑤ draw_midline | 156次赋值+直线绘制 | ~200 | ~0.01 ms |
| ⑥ node_proc | 状态机判断 | <100 | ~0.005 ms |
| ⑦ calc_image_error | 40次加法 | 40 | ~0.001 ms |
| **总计** | | | **~0.34 ms** |

### 4.3 处理时间 vs 帧间隔

```
摄像头帧间隔 = 10 ms（100 FPS）
图像处理时间 ≈ 0.34 ms
CPU利用率 ≈ 0.34 / 10 = 3.4%

→ 大量空闲时间用于PID控制、蓝牙通信、OLED显示
→ 不会丢帧
```

## 5. 逐飞库计时函数

### 5.1 system_start() + system_getval_us()

**最推荐的方式**，精度微秒级：

```c
#include "zf_driver_timer.h"

// 测量 image_proc() 耗时
system_start();                          // 记录起始时间戳
image_proc();                            // 执行图像处理
uint32 time_us = system_getval_us();     // 获取经过的微秒数

// 显示到OLED
ips114_show_int(0, 0, time_us, 4);       // 显示 xxxx us
```

**原理**：读取STM（系统定时器模块）的64位计数器，减去起始值，除以时钟频率换算为微秒。

### 5.2 帧率统计

```c
// 全局变量
static uint32 fps_count = 0;
static float fps = 0.0f;

// 在 image_proc() 被调用时（每处理一帧）
fps_count++;

// 每秒更新一次帧率（在 PIT 1ms 中断中）
static uint16 fps_timer = 0;
if (++fps_timer >= 1000)     // 1秒到了
{
    fps = fps_count;          // 这1秒内处理了多少帧
    fps_count = 0;
    fps_timer = 0;
}
```

### 5.3 逐飞库可用的计时函数汇总

| 函数 | 头文件 | 精度 | 用法 |
|------|--------|------|------|
| `system_start()` + `system_getval_us()` | zf_driver_timer.h | 1us | 最推荐 |
| `system_delay_us()` | zf_driver_delay.h | 1us | 仅延时，不测量 |
| `pit_ms_init()` | zf_driver_pit.h | 1ms | 定时中断 |
| STM底层 `IfxStm_getLower()` | IfxStm.h | 10ns | 底层硬件 |

### 6.2 添加处理时间与帧率显示

在 `image_proc()` 中添加计时，在主循环中显示：

```c
// === image.c 中添加 ===
float deal_time = 0.0f;      // 处理时间（微秒）
float cam_fps = 0.0f;        // 摄像头帧率
static uint32 fps_cnt = 0;   // 帧计数

void image_proc(void)
{
    if (mt9v03x_finish_flag_1)
    {
        mt9v03x_finish_flag_1 = 0;

        system_start();       // ★ 开始计时

        image_scale(mt9v03x_image_1);
        image_binarize(orig_image);
        search_line_8();
        get_lost_feature();
        draw_midline();
        node_proc();
        calc_image_error();

        deal_time = (float)system_getval_us();  // ★ 结束计时，获取微秒
        fps_cnt++;
    }
}

// === cpu0_main.c 中添加帧率统计 ===
static uint16 fps_timer = 0;
if (++fps_timer >= 1000)  // 每秒更新
{
    cam_fps = fps_cnt;
    fps_cnt = 0;
    fps_timer = 0;
}

// === 显示 ===
if (!start_flag)
{
    ips114_show_gray_image(0, 0, bin_image[0], COL, ROW, COL, ROW, 0);
    ips114_show_int(200, 0, (int)image_err, 3);
    ips114_show_int(200, 20, (int)deal_time, 4);  // 处理时间 us
    ips114_show_int(200, 40, (int)cam_fps, 3);     // 帧率 FPS
}
```

## 7. 本项目实际帧率估算

### 7.1 系统时间线（10ms一帧）

```
时间轴（0ms ~ 10ms）：

0ms     摄像头VSYNC → DMA开始搬运第N帧
        ↓
0~2ms   DMA搬运中（CPU空闲，执行PID控制等）
        ↓
2ms     DMA完成 → mt9v03x_finish_flag_1 = 1
        ↓
2~2.34ms image_proc() 执行（~0.34ms）
        ↓
2.34ms  处理完成 → image_err 更新 → PID用新误差
        ↓
2.34~10ms CPU空闲 → PID继续用最新误差控制电机
        ↓
10ms    摄像头VSYNC → 第N+1帧开始
```

### 7.2 关键结论

| 指标 | 数值 |
|------|------|
| 摄像头帧率 | 100 FPS |
| 帧间隔 | 10 ms |
| 图像处理时间 | ~0.34 ms |
| CPU利用率 | ~3.4% |
| 剩余空闲时间 | ~9.66 ms |
| PID控制周期 | 2ms（在空闲时间中执行） |
| **会丢帧吗？** | **不会** |

### 7.3 如果加了更复杂的算法

| 场景 | 处理时间 | 帧率 | 是否丢帧 |
|------|---------|------|---------|
| 当前（八邻域+四方位） | ~0.34ms | 100fps | 不会 |
| 加腐蚀去噪 | ~1ms | 100fps | 不会 |
| 加虚线补线 | ~2ms | 100fps | 不会 |
| 加环岛/停车线识别 | ~3ms | 100fps | 不会 |
| 全幅752×480处理 | ~8ms | 50fps | 不会 |
| 极端复杂（环岛+断路+补线） | ~5ms | 100fps | 不会 |

**你的项目有大量算力余量——TC264 300MHz 处理 156×60 的图像绰绰有余。**
