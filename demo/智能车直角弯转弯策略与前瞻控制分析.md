## 1. 问题现象

```
慢速（1m/s）：直角弯能转过去 ✓
快速（3m/s+）：直角弯转不出去，车子冲出去 ✗
```

车子感觉"慢半拍"——明明检测到拐点了，但车到路口时还没转过来。

---

## 2. 根本原因分析

直角弯转不出去不是单一原因，是**三个因素叠加**：

```
┌────────────────────────────────────────────────┐
│                                                │
│  1. 电机响应延迟（硬件限制，无法消除）            │
│     电机从 0 升到目标转速需要 50~100ms           │
│                                                │
│  2. 车身惯性（物理定律，只能补偿不能消除）         │
│     速度越快，刹车/转向时滑行距离越大              │
│                                                │
│  3. 前瞻不够（软件问题，可以优化）                │
│     只看到近处的拐点，来不及提前转弯               │
│                                                │
└────────────────────────────────────────────────┘
```

三者叠加的效果：

```
检测到拐点 → 电机开始响应（50ms延迟）→ 电机达到目标转速（50~100ms）
                                        → 车身开始实际转向
                                        → 转向过程中车还在往前滑
                                        → 到达路口时：要么还没转，要么转过了
```

## 3. 电机响应延迟详解

### 3.1 电机不是开关

```
理想电机（不存在）：
  PWM 0 → PWM 8000：瞬间到达 → 无延迟

现实电机：
  PWM 0 → PWM 8000：
    0ms    : 0 RPM
    10ms   : 1000 RPM（还在加速）
    20ms   : 3000 RPM（加速中）
    30ms   : 5500 RPM（接近目标）
    50ms   : 7500 RPM（基本到位）
    80ms   : 8000 RPM（稳定）
```

### 3.2 响应延迟的组成

```
总延迟 = 电气延迟 + 机械延迟 + 控制延迟

电气延迟：~1ms（PWM 信号传输到驱动芯片）
机械延迟：~30~80ms（转子从静止加速到目标转速）
控制延迟：~5ms（你的 PID 每 5ms 更新一次 PWM）

总计：约 40~90ms（取决于负载和目标速度）
```

### 3.3 延迟期间车走了多远

```
延迟时间 × 车速 = 滑行距离

  1m/s × 50ms = 5cm
  2m/s × 50ms = 10cm
  3m/s × 50ms = 15cm
  4m/s × 50ms = 20cm
```

这 5~20cm 就是"来不及"的直接原因——车在这段距离内还是直走的，虽然 PWM 已经在打方向了，但电机还没转起来。

### 3.4 速度越快延迟越大

```
低速时：电机负载小，加速快 → 延迟 ~30ms
高速时：电机负载大（空气阻力+摩擦），加速慢 → 延迟 ~50~80ms
```

## 4. 前瞻距离与速度的关系

### 4.1 核心公式

```
所需前瞻距离 = 车速 × (电机响应时间 + 转弯执行时间)

简化为：
所需前瞻距离 ≈ 车速 × 总延迟时间
```

### 4.2 不同速度下的前瞻需求

假设总延迟 ≈ 80ms（电机响应 + 转弯执行）：

| 车速 | 所需前瞻距离 | 对应图像行（估算） |
|------|------------|-----------------|
| 1 m/s | 8 cm | row 40~50（近处） |
| 2 m/s | 16 cm | row 25~35（中距离） |
| 3 m/s | 24 cm | row 15~25（远距离） |
| 4 m/s | 32 cm | row 5~15（很远） |

### 4.3 前瞻距离不够的后果

```
前瞻 = 8cm，车速 = 1m/s：
  发现拐点 → 8cm 后到达路口 → 电机已响应完 → 正好在转 ✓

前瞻 = 8cm，车速 = 3m/s：
  发现拐点 → 8cm 只需 2.7ms → 但电机需要 80ms → 还没开始转就到了 ✗
  
前瞻 = 24cm，车速 = 3m/s：
  发现拐点 → 24cm 需要 80ms → 电机刚好响应完 → 正好在转 ✓
```

### 4.4 用代码来理解

```c
// 当前代码（固定前瞻）
find_guaidian(ROW - 5, 40);  // 永远看 row 40~55（约 8cm 远）

// 这个前瞻距离只够 1m/s 用
// 3m/s 时需要看 row 15~25（约 24cm 远）
// 4m/s 时需要看 row 5~15（约 32cm 远）
```

## 5. 摄像头角度对前瞻的影响

### 5.1 摄像头俯角与可视距离

```
俯角大（朝下 60°）：
  ┌─────────────────┐
  │  摄像头朝下      │
  │     \  60°       │
  │      \           │
  │       \          │
  │        ● 近处    │  → 只能看到车前方 10~20cm
  │        路面      │  → 前瞻短，适合低速
  └─────────────────┘

俯角小（朝下 30°）：
  ┌─────────────────┐
  │  摄像头朝前      │
  │     \  30°       │
  │      \           │
  │       \          │
  │        \         │
  │         ● 远处   │  → 能看到车前方 30~50cm
  │         路面     │  → 前瞻长，适合高速
  └─────────────────┘
```

### 5.2 常见误区

```
误区："摄像头抬高 = 看得远"

实际情况：
  摄像头抬高 → 俯角变大 → 看得更近 ✗
  
  因为摄像头位置高了，朝下看的角度更陡，
  同样的画面范围对应更近的地面区域。
```

### 5.3 正确做法

```
想看得远：
  ✓ 摄像头往前倾（减少俯角），而不是往上抬
  ✓ 软件扩大搜索范围（减小 find_guaidian 的 end 值）
  ✓ 配合去噪减少远处误判

想看近处更清楚：
  ✓ 摄像头朝下更多（增大俯角）
  ✓ 适合低速精确循迹
```

### 5.4 摄像头角度与速度的匹配

| 车速 | 推荐俯角 | 前瞻距离 | 说明 |
|------|---------|---------|------|
| 1~2 m/s | 50°~60° | 10~15cm | 看近处，精度优先 |
| 2~3 m/s | 35°~45° | 15~25cm | 平衡 |
| 3~4 m/s | 25°~35° | 25~35cm | 看远处，提前量优先 |

## 6. 固定误差转弯法分析

### 6.1 你的代码做了什么

```
直角弯转弯流程：

1. find_guaidian() 找到拐点
2. corner_turn() / plan_turn() 决定转向方向
3. 进入 NODE_TURNING 状态
4. bias_left() / bias_right() 在拐点处画一条固定线
   → mid_line 被强制偏移
   → image_err 变成一个大的固定值
   → PID 输出最大转向
   → 电机一左一右打方向
5. yaw 角到达目标 → 回正 → 回到 NODE_NONE
```

### 6.2 类比

```
固定误差转弯 = 蒙眼开车到路口，听到"到了"就方向盘一把打死

不管路口是急弯还是缓弯，不管车速多少，
都是同一把方向、同一个力度。
```

### 6.3 这个方法能不能用

**能用，4m/s 大佬验证过了。** 但前提是：

```
前提条件：
  1. 图像处理够稳（八邻域去噪 + 四方位检测）
  2. 拐点检测够准（不误判）
  3. 前瞻距离够远（来得及响应）

只要这三个条件满足，固定误差转弯完全够用。
不需要搞平滑轨迹、不需要 S 形弯道规划。
```

### 6.4 为什么简单方法反而有效

```
复杂方法（轨迹规划）：
  优点：转弯平滑，过弯速度快
  缺点：代码复杂，调试困难，容易出 bug
  适用：工业级自动驾驶

简单方法（固定误差）：
  优点：代码简单，稳定可靠，容易调试
  缺点：转弯粗暴，有轻微过冲
  适用：智能车竞赛（速度有限，赛道简单）
```

## 7. 八邻域去噪 + 前瞻的配合

### 7.1 矛盾

```
想提速 → 需要看更远（前瞻拉大）
看更远 → 远处噪声多 → 拐点误判
误判 → 提前乱转弯 → 比不转还糟
```

### 7.2 解决方案

```
八邻域去噪 → 把远处的孤立噪声点去掉
    → 前瞻可以拉远而不误判
    → 速度就能上去

这就是四川 4m/s 队伍的核心秘密：
  不是转弯算法多牛，是图像处理够干净。
```

### 7.3 去噪与前瞻的配合效果

```
没有去噪，前瞻 row 40：
  误判率低 ✓  但速度上不去 ✗

没有去噪，前瞻 row 15：
  速度够了 ✓  但误判率爆炸 ✗

有去噪，前瞻 row 15：
  速度够了 ✓  误判率可接受 ✓  ← 这就是目标状态
```

### 7.4 去噪强度的选择

```
去噪太弱（same < 2）：
  → 远处噪声还在 → 误判多

去噪适中（same < 3）：← 推荐
  → 远处噪声基本去掉 → 白线边缘保留

去噪太强（same < 4）：
  → 白线边缘也被去掉 → 扫线丢失
```

## 8. 速度自适应前瞻方案

### 8.1 原理

```
前瞻距离 ∝ 车速

车速快 → 看更远（end 值减小）
车速慢 → 看更近（end 值增大）
```

### 8.2 实现思路（不改代码，仅说明）

```
// 伪代码
actual_speed = 从编码器计算实际速度 (m/s)

// 根据速度计算前瞻范围
if (actual_speed < 1.5) {
    guaidian_end = 40;     // 低速：看近处
} else if (actual_speed < 2.5) {
    guaidian_end = 30;     // 中速：看中距离
} else if (actual_speed < 3.5) {
    guaidian_end = 20;     // 高速：看远处
} else {
    guaidian_end = 10;     // 极速：看很远
}

find_guaidian(ROW - 5, guaidian_end);
```

### 8.3 前提条件

要做速度自适应，需要先有：
1. **编码器读取实际速度**（硬件已有，代码未实现速度计算）
2. **速度闭环控制**（当前是开环，base_speed 直接输出）

### 8.4 当前阶段不建议做

```
原因：
  1. 开环控制下，实际速度不等于设定速度
  2. 编码器→速度的换算需要标定（轮子直径、编码器线数）
  3. 增加了调试复杂度

建议：
  先用固定前瞻 + 手动调到最佳值
  等上了速度闭环再做自适应
```

## 9. 实战调参方法

### 9.1 第一步：确定当前最佳前瞻值

```
固定 base_speed 不变
只改 find_guaidian 的 end 值

从 end=40 开始，每次减小 5：
  40 → 35 → 30 → 25 → 20 → 15 → 10

记录每个值的表现：
  - 直角弯能不能转过去？
  - 有没有提前误转？
  - 有没有过冲？

找到"刚好能转过去"的最小 end 值 = 你的最佳前瞻
```

### 9.2 第二步：提速后重新调

```
加大 base_speed
重复第一步

你会发现：速度越快，最佳 end 值越小（需要看得更远）
```

### 9.3 调参记录表

```
base_speed = 1200：
  end=40 → 能转 ✓，无误判
  end=30 → 能转 ✓，无误判
  end=20 → 能转 ✓，偶尔误判
  end=10 → 能转 ✓，误判多 ✗
  → 最佳 end = 20

base_speed = 2000：
  end=40 → 转不过去 ✗（太近了）
  end=30 → 能转 ✓，无误判
  end=20 → 能转 ✓，无误判
  end=10 → 能转 ✓，偶尔误判
  → 最佳 end = 20

base_speed = 3000：
  end=40 → 转不过去 ✗
  end=30 → 转不过去 ✗（还是太近）
  end=20 → 能转 ✓，偶尔误判
  end=10 → 能转 ✓，无误判
  → 最佳 end = 10
```

### 9.4 关键发现

```
不同速度需要不同的前瞻值：
  慢速 → end 大（看近）
  快速 → end 小（看远）

如果只用一个固定值，只能适配一个速度区间。
```

## 10. 从1m/s到4m/s的完整路径

### 10.1 阶段一：1~2m/s（当前水平）

```
目标：稳定跑完一圈
方法：
  - 固定前瞻 end=40
  - 固定误差转弯
  - 八邻域去噪（已加）
  - 基础 PID 调好

关键指标：
  - 直角弯能转过去
  - 不丢线
  - 不误判
```

### 10.2 阶段二：2~3m/s

```
目标：提速后弯道还能过
方法：
  - 前瞻拉远 end=25~30
  - 去噪强度确认够用
  - PID 参数重新微调（速度变了，PID 要跟）
  - 启动脉冲调好（克服静摩擦）

关键指标：
  - 直角弯能转过去
  - 无明显过冲
  - 无误判
```

### 10.3 阶段三：3~4m/s

```
目标：接近竞赛水平
方法：
  - 前瞻拉到 end=10~20
  - 八邻域去噪 + 四方位路径检测
  - 考虑速度闭环（编码器反馈）
  - 考虑速度自适应前瞻

关键指标：
  - 直角弯稳定通过
  - 速度损失最小
  - 零误判
```

### 10.4 每个阶段的核心工作

```
1~2m/s：调 PID + 去噪 + 基础前瞻
         ↑ 你现在在这里

2~3m/s：拉前瞻 + 重新调 PID + 启动脉冲

3~4m/s：速度闭环 + 自适应前瞻 + 四方位检测

4m/s+：  全部优化到位 + 硬件调优（电机、轮子、赛道材质）
```

## 总结

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 直角弯转不出去 | 前瞻不够 + 电机延迟 | 拉远前瞻（减小 end 值） |
| 前瞻拉远后误判 | 远处噪声多 | 八邻域去噪 |
| 速度越快越转不过去 | 所需前瞻随速度增大 | 速度自适应前瞻（后续做） |
| 转弯过冲/甩尾 | 固定误差太猛 | 当前可接受，后续优化 |
| 电机启动卡住 | 静摩擦力大 | 启动脉冲（已加） |

**核心结论：图像处理 > 转弯算法。去噪做好了，简单方法也能跑 4m/s。**
