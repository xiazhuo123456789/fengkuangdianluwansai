## 一、为什么需要惯导融合摄像头

### 1.1 纯摄像头方案的致命弱点

| 问题 | 具体表现 | 对你的赛道的影响 |
|------|----------|-----------------|
| **直角弯丢线** | 摄像头视野有限，直角弯瞬间看不到前方赛道 | ⚠️ 非常严重 — 你全是直角弯 |
| **中线跳变** | 进入直角弯时中线突然跳到一侧，舵机剧烈摆动 | ⚠️ 非常严重 |
| **响应延迟** | 摄像头帧率30~60fps + 图像处理耗时，造成感知延迟 | ⚠️ 冲刺时尤为明显 |
| **十字/T字干扰** | 多方向赛道线同时出现，不知道该走哪条 | ⚠️ 你的赛道有T字和十字 |
| **丢线恢复慢** | 丢线后只能靠图像回溯，恢复耗时长 | ⚠️ 冲刺过弯丢线后无法及时恢复 |

### 1.2 IMU能解决什么

| IMU优势 | 说明 |
|---------|------|
| **高频采样** | 100~1000Hz，远高于摄像头30~60fps |
| **航向角积分** | 陀螺仪积分可精确判断转弯进度（转了多少度） |
| **不受光照影响** | 角速度数据与环境光线无关 |
| **丢线接管** | 摄像头丢线时，IMU可短暂维持航向控制 |
| **直角弯判断** | 转到约90° = 直角弯完成，判断精确可靠 |

### 1.3 融合的核心思路

```
┌─────────────┐     ┌─────────────┐
│   摄像头     │     │   IMU       │
│  寻迹+识别   │     │ 航向角积分   │
└──────┬──────┘     └──────┬──────┘
       │                   │
       ▼                   ▼
┌─────────────────────────────────┐
│         融合决策层               │
│  正常寻迹：摄像头主导             │
│  直角弯：IMU接管判断90°          │
│  丢线：IMU航向恢复               │
│  十字/T字：IMU维持姿态           │
│  冲刺：IMU+编码器预判            │
└──────────────┬──────────────────┘
               ▼
       ┌──────────────┐
       │  舵机+电机    │
       │  PID控制      │
       └──────────────┘
```

## 三、IMU基本原理

### 3.1 陀螺仪积分航向角

陀螺仪测量载体绕各轴的**角速度** ω，对时间积分得到航向角：

```
航向角 θ(n) = θ(n-1) + ωz(n) × Δt
```

- `ωz` = Z轴角速度（绕垂直轴旋转）
- `Δt` = 采样周期（建议 ≤5ms，即 ≥200Hz）
- 累加得到当前转过的角度

**你的场景下**：转到约 **90°** = 直角弯完成，转到约 **180°** = U型掉头完成。

### 3.2 零偏漂移问题

| 误差源 | 影响 | 量化示例 |
|--------|------|---------|
| **温度漂移** | 温度变化导致零偏缓慢变化 | 温度系数 ~0.01~0.03 °/s/°C |
| **时间漂移** | 零偏随时间随机变化 | 随机游走 |
| **上电漂移** | 上电后前几分钟变化大 | 需预热5~10秒 |

**漂移后果量化**：

| 积分时间 | 航向角误差（零偏0.01°/s时） |
|---------|--------------------------|
| 1秒 | 0.01° |
| 10秒 | 0.1° |
| 1分钟 | 0.6° |
| 10分钟 | 6° |

### 3.3 安装方向约定

| 轴向 | 方向 | 用途 |
|------|------|------|
| **X轴** | 指向车头 | 测量前后加速度 |
| **Y轴** | 指向车侧方 | 测量侧向加速度 |
| **Z轴** | 垂直向上 | 测量yaw角速度 |

## 四、融合算法对比

### 4.1 五种核心算法综合对比

| 对比维度 | 互补滤波 | 卡尔曼滤波(KF) | 扩展卡尔曼(EKF) | 滑动平均 | Mahony |
|---------|---------|---------------|----------------|---------|--------|
| **原理** | 频域互补加权 | 最优线性递推 | 非线性线性化+递推 | 统计平均 | SO(3)互补+PI |
| **计算量** | 10-20 FLOPS | 数百~数千 | 数千~上万 | 极低 | 100-200 FLOPS |
| **精度** | 一般 | 良好 | **最优** | 仅平滑 | 良好~优秀 |
| **参数个数** | 1 (alpha) | 2 (Q, R) | 2+ | 1 (N) | 2 (Kp, Ki) |
| **调参难度** | 容易 | 较难 | 困难 | 容易 | 中等 |
| **内存占用** | 极小 | 中等 | 较大 | 中等 | 极小 |
| **多传感器融合** | 否 | 是 | **是（最优）** | 否 | 是 |
| **零偏在线估计** | 否 | 可扩展 | **是** | 否 | **是(I项)** |
| **适用MCU** | 8-bit+ | Cortex-M3+ | **Cortex-M4/FPU+** | 8-bit+ | Cortex-M0+ |

### 4.2 各MCU推荐方案

| MCU平台 | 推荐算法 | 理由 |
|---------|---------|------|
| **STM32F103** (72MHz, 无FPU) | **Mahony滤波** + 滑动平均预处理 | 计算量可控，Ki自动补偿零偏 |
| **STM32F407** (168MHz, 有FPU) | **Mahony滤波**(推荐) 或 简化EKF | FPU加速，性价比最高 |
| **RT1062/RT1064** (600MHz) | **EKF** | 性能充裕，可做深度融合 |

### 4.3 航向角积分方法对比

| 对比维度 | 欧拉角积分 | 四元数积分(推荐) |
|---------|-----------|-----------------|
| 万向节锁 | **有** | **无** |
| 计算量 | 较大(含三角函数) | 较小(仅乘加) |
| 数值稳定性 | 一般 | 好(归一化即可修复) |
| 行业采用 | 少见 | **主流** |
| 内存 | 3个float | 4个float |

> **强烈推荐使用四元数积分**，最终输出航向角时再转换为欧拉角。

## 五、各场景融合策略（针对你的赛道）

### 5.1 直角弯处理（最核心）

**纯摄像头难点**：视野盲区、中线跳变、边界线突变消失、响应延迟

**IMU融合方案**：

| 阶段 | 传感器分工 | 具体操作 |
|------|-----------|---------|
| **接近弯道** | 摄像头检测 | 扫描边界线斜率突变，触发直角弯标志位 |
| **入弯减速** | 协同控制 | 速度降至直道的30%~50%，梯度减速 |
| **转弯执行** | **IMU主导** | 航向角积分判断转弯进度 |
| **转够90°** | **IMU判断** | 航向角累计变化达90°时判定完成 |
| **出弯恢复** | 摄像头接管 | 摄像头重新找到线后切回巡线模式 |

**核心判断逻辑**：
- 航向角变化 < 85°：保持满舵
- 航向角变化 85°~95°：开始回正
- 摄像头重新找到线：切换回摄像头控制

### 5.2 T字路口处理

| 阶段 | 传感器分工 | 具体操作 |
|------|-----------|---------|
| **识别** | 摄像头 | 某侧边界线完全消失 + 另一侧横向延伸 |
| **方向决策** | 状态机 | 全局计数器记录已通过路口数，预设方向 |
| **中心穿越** | **IMU+编码器** | 航迹推算穿越无赛道线的中心区域 |
| **转弯执行** | **IMU** | 设定目标航向角±90°，控制转向 |
| **恢复** | 摄像头 | 重新检测到赛道线后恢复巡线 |

### 5.3 十字路口处理

| 阶段 | 传感器分工 | 具体操作 |
|------|-----------|---------|
| **识别** | 摄像头 | 四方向边界线同时延伸，"井"字形特征 |
| **通过策略** | **IMU维持直行** | 锁定当前航向角，PID控制保持航向不变 |
| **穿越距离** | IMU+编码器 | 控制穿越距离，避免过早/过晚 |
| **方向选择** | 状态机 | 默认直行，按预设规则选择 |

### 5.4 丢线恢复

| 阶段 | 操作 |
|------|------|
| **丢线检测** | 摄像头无法提取有效边界线 → 触发丢线标志 |
| **模式切换** | 从"摄像头巡线"切至"IMU惯性导航" |
| **航向维持** | IMU陀螺仪角速度PID维持丢线前航向 |
| **搜索恢复** | 偏差超阈值时蛇形搜索，编码器累计距离做超时保护 |
| **平滑切回** | 3~5帧过渡融合，逐渐增加摄像头权重 |

### 5.5 冲刺阶段

| 要素 | 说明 |
|------|------|
| **IMU高频采样** | 保持 ≥500Hz，确保角速度数据及时 |
| **前馈减速** | 根据弯道距离提前减速，梯度减速 |
| **前馈打舵** | 弯道入口前2~3个前瞻点距离处开始打舵 |
| **直道稳定** | IMU监测直线行驶稳定性，抑制横向抖动 |

### 5.6 各场景策略总结表

| 场景 | 传感器分工 | 核心算法 | 速度策略 | 关键难点 |
|------|-----------|---------|---------|---------|
| **直角弯** | 摄像头检测 + IMU执行转弯 | 边界线突变检测 + 航向角积分90° | 降至30%~50%，弯中低速 | 视野盲区、中线跳变 |
| **T字路口** | 摄像头识别 + IMU航迹推算 | 像素统计 + 航迹推算穿越 | 进入前减速，中心低速转向 | 方向决策、推算精度 |
| **十字路口** | 摄像头识别 + IMU维持直行 | 四方向检测 + 航向角锁定 | 适度减速，稳定直行通过 | 干扰线误动作 |
| **丢线恢复** | IMU完全接管 + 编码器控制距离 | 丢线触发 + 角速度PID + 蛇形搜索 | 丢线后降速 | 恢复切换平滑性 |
| **冲刺** | IMU高频 + 摄像头远距预判 | 前馈+反馈复合控制 | 直道全力加速 | 高速振动、制动距离 |

## 六、航迹推算（Dead Reckoning）技术

### 6.1 基本原理

航迹推算在已知起始位置基础上，通过累积测量推算当前位置：

| 步骤 | 公式 | 说明 |
|------|------|------|
| 航向角更新 | θ(n+1) = θ(n) + ωz × Δt | 陀螺仪Z轴角速度积分 |
| 位置更新 | x(n+1) = x(n) + Δd × cos(θ) | 编码器提供Δd |
| 位置更新 | y(n+1) = y(n) + Δd × sin(θ) | 编码器提供Δd |

**实际常用方案**：编码器提供里程增量 + IMU提供航向角

### 6.2 误差累积量化分析

| 行驶时间 | 航向角漂移 | 5米处横向位置误差 |
|---------|-----------|-----------------|
| 1秒 | ~0.003° | ~0.3 mm |
| 5秒 | ~0.015° | ~1.3 mm |
| 10秒 | ~0.03° | ~2.6 mm |
| 30秒 | ~0.09° | ~7.9 mm |
| 1分钟 | 0.5~5° | 4.4~44 cm |

### 6.3 编码器辅助方法

| 方法 | 原理 | 适用性 |
|------|------|--------|
| 简单融合 | 编码器距离 + IMU航向 | 最常见，实现简单 |
| 互补滤波 | 陀螺仪(高频) + 加速度计(低频)互补 | 计算量小，适合MCU |
| EKF | 状态含位置、航向、零偏 | 精度最优，计算量大 |
| 航向角加权融合 | θ = α×θ_gyro + (1-α)×θ_encoder | 编码器差速辅助航向 |
| 零速检测(ZUPT) | 静止时锁定积分器 | 抑制速度漂移 |

### 6.4 赛道地图匹配

| 应用 | 方法 |
|------|------|
| 赛前地图构建 | 手动遥控跑赛道，记录中心线坐标 |
| 实时匹配 | 将DR推算位置与地图最近点匹配 |
| 误差修正 | 匹配后约束到赛道中心线，消除横向漂移 |
| 弯道特征匹配 | 利用直角弯已知位置进行绝对定位校正 |

### 6.5 实际精度（你最关心的）

| 距离 | 纯IMU积分 | IMU+编码器 | IMU+编码器+地图匹配 |
|------|----------|-----------|-------------------|
| 1~2米（直角弯内） | ±2~5 cm | ±1~3 cm | ±1~2 cm |
| 5~10米（冲刺段） | ±15~50 cm | ±5~15 cm | ±2~5 cm |
| 100米（一整圈） | 米级（不可用） | ±30~80 cm | ±5~10 cm |

> **关键结论**：直角弯内（1~2米）精度完全够用！短距离航迹推算是最实用的场景。

### 10.2 注意事项清单

|---------|---------|-----------|
| **远离电磁干扰源** | 远离电机、电磁铁、MOS管 | 磁力计航向错误 |
| **避免与驱动板共板** | 加速度计和电机驱动分开放 | 电流尖峰传导噪声 |

| **时间同步** | 摄像头帧与IMU数据时间戳对齐 | 融合数据错位 |

## 总结

针对你的赛道（**全是直角弯、T字路口、十字路口，无弯道环岛**），核心结论：

1. **IMU融合非常有价值** — 你的赛道全是直角弯，IMU航向角积分判断90°转弯是最实用的技术
2. **推荐方案：摄像头 + ICM-20948(或BMI088) + Mahony滤波**
3. **核心优势**：直角弯过弯速度提升2~3倍（从0.5m/s提升到1.0~1.5m/s）
4. **直角弯策略**：摄像头检测弯道 → IMU接管执行转弯 → 航向角积分到90° → 出弯恢复
5. **短距离航迹推算**：直角弯内1~2米精度达±1~5cm，完全满足需求
6. **开发建议**：先实现MPU6050/ICM-20948基础融合，再逐步加入直角弯模板和冲刺策略
