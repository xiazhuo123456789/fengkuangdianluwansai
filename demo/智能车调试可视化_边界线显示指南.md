## 问题背景

> "你的打框会显示在图像上吗？" — "要显示，还有扫到的边界也要显示，不然很多问题只能靠猜。"

当前屏幕只显示灰度图和 error 数值，**看不到扫线结果**，导致：
- 不知道左右边界在哪里
- 不知道中线偏没偏
- 不知道拐点检测到没有
- 不知道检测框对不对
- 所有问题只能靠猜

## 启用步骤（共3步）

### 步骤1：取消注释 `debug_show_boundary()` 函数

打开 `image.c`，找到文件最末尾的：

```c
// ========== 调试可视化：显示边界线 + 检测框（需要时取消注释） ==========
// void debug_show_boundary(void)
// {
//     ...
// }
```

**删掉这个区域所有行开头的 `//`**，使函数变为有效代码。

### 步骤2：在 `image_proc()` 中调用

打开 `image.c`，找到 `image_proc()` 函数（约第897行）：

```c
void image_proc(void)
{
    if (mt9v03x_finish_flag_1)
    {
        mt9v03x_finish_flag_1 = 0;
        image_scale(mt9v03x_image_1);
        image_binarize(orig_image);
        search_line();
        node_proc(bin_image);
        calc_image_error();
        draw_rect();
        debug_show_boundary();   // ← 在这里加这一行
    }
}
```

在 `draw_rect();` 下面加一行 `debug_show_boundary();`。

### 步骤3：删除 cpu0_main.c 中的重复显示

因为 `debug_show_boundary()` 内部已经调用了 `ips114_show_gray_image()`，
所以 `cpu0_main.c` 中原来的显示代码需要注释掉，否则会刷两次屏：

```c
// cpu0_main.c 中注释掉这行：

// ips114_show_int(200, 00, (int)image_err, 3);
```

## 函数功能详解

```c
void debug_show_boundary(void)
{
    // 1. 显示灰度图（156×60 像素，占屏幕左侧）
    ips114_show_gray_image(0, 0, bin_image[0], COL, ROW, COL, ROW, 0);

    // 2. 在灰度图上逐行画边界点
    for (uint8 row = 0; row < ROW; row++)
    {
        // 左边界：红色，2像素宽
        ips114_draw_point(l_border[row], row, RGB565_RED);
        ips114_draw_point(l_border[row]+1, row, RGB565_RED);

        // 右边界：蓝色，2像素宽
        ips114_draw_point(r_border[row], row, RGB565_BLUE);
        ips114_draw_point(r_border[row]-1, row, RGB565_BLUE);

        // 中线：绿色，2像素宽
        ips114_draw_point(mid_line[row], row, RGB565_GREEN);
        ips114_draw_point(mid_line[row]+1, row, RGB565_GREEN);
    }

    // 3. 画检测矩形框（4条红线）
    ips114_draw_line(RECT_LEFT, RECT_TOP, RECT_RIGHT, RECT_TOP, RGB565_RED);
    // ... 共4条线

    // 4. 标记拐点（黄色十字，5个像素点组成）
    if (l_guaidian != 0) { ... }  // 左拐点
    if (r_guaidian != 0) { ... }  // 右拐点

    // 5. 右侧显示文字信息（不覆盖灰度图）
    ips114_show_string(160, 0, "L:");   // 左拐点行号
    ips114_show_string(160, 16, "R:");  // 右拐点行号
    ips114_show_string(160, 32, "N:");  // 节点状态
    ips114_show_string(160, 48, "E:");  // 图像误差
}
```

## 如何通过显示结果判断问题

### 场景1：直道正常

```
预期显示：
🔴🔵边界平行，🟢中线在正中间
检测框内全白（赛道区域）
无黄色拐点标记
L:0  R:0  N:0  E:≈0
```

### 场景2：弯道检测正常

```
预期显示：
🔴左边界或🔵右边界出现明显弯折
🟢中线偏向一侧
🟡拐点标记出现在弯折处
N:1 或 N:2（进入 DETECTED/TURNING）
```

### 场景3：进状态晚（当前问题）

```
症状：
🟡拐点标记出现在图像底部（row>40）
但此时车已经到弯道口了
N:0 持续很久才变成 N:2
```

### 场景4：边界丢失

```
症状：
🔴左边界消失（l_border[row]=0）
或🔵右边界消失（r_border[row]=155）
中线偏到一侧极限
→ 说明二值化阈值不对或曝光问题
```

### 场景5：检测框位置不对

```
症状：
红色检测框没有覆盖到路口区域
→ 说明 RECT_LEFT/RIGHT/TOP/BOTTOM 参数需要调整
```

## 性能影响

| 项目 | 耗时 |
|------|------|
| ips114_show_gray_image | ~2ms |
| 60行 × 3颜色 × 2像素 = 360次 draw_point | ~1.5ms |
| 4条 draw_line（检测框） | ~0.3ms |
| 拐点标记（最多10个点） | ~0.05ms |
| 文字显示（4行） | ~0.2ms |
| **总计** | **~4ms** |

加上原有 image_proc 的 ~5ms，总计约 **9ms/帧**，FPS 会降到 ~60 左右，可以接受。
