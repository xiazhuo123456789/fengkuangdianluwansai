## 一、你的问题：速度一提升，直角弯就转不过来

### 最终结论：不是单一原因，是多个因素叠加

```
你遇到的现象：
  低速时能转过直角弯 ✅
  提速后直角弯转不过来，直接冲出去 ❌

原因分析（按影响大小排序）：
  1. 🔴 最致命：没有弯道减速（代码被注释掉了！）
  2. 🔴 很严重：转向PID没有积分项，转弯时角度不够
  3. 🟠 有影响：图像误差计算没有加权，远处信息被稀释
  4. 🟠 有影响：陀螺仪只用来减速（阻尼），没有用来辅助转向
  5. 🟡 有影响：转弯完成判定太宽松（20度容差）
```

## 二、逐项分析

### 问题 1：弯道减速代码被注释掉了！（最致命）

你的 `control.c` 第89-93行：

```c
//  // 直角转弯时减速
//        if(node_state == NODE_TURNING && (turn_dir == TURN_LEFT || turn_dir == TURN_RIGHT))
//          {
//            actual_speed = (int)(base_speed * TURN_SPEED_RATIO);
//          }
```

**这段代码是注释掉的！** `TURN_SPEED_RATIO = 0.5f`，意思是转弯时速度减半。但因为被注释了，车子在直角弯时保持 `base_speed = 150` 全速通过。

**物理原理：**
```
转弯需要的向心力 F = m × v² / r

速度翻倍 → 向心力需要4倍 → 轮胎抓地力不够 → 打滑冲出去

低速时：v=80, F = m×80²/r = 6400m/r → 轮胎够用 ✅
高速时：v=150, F = m×150²/r = 22500m/r → 轮胎不够 ❌（需要3.5倍的力）
```

### 问题 2：转向PID没有积分项

你的转向PID公式（`control.c` 第213行）：
```c
steer_value = kp*error + kp2*error*|error| + kd*error_diff - (gyro*gkd)/100;
```

**只有 P + 非线性P + D + 陀螺阻尼，没有 I（积分）项。**

```
有I项：转弯时持续累积误差 → 逐渐加大转向力 → 转到位
没有I项：转弯时误差持续存在但不累积 → 转向力不够 → 转不过来

直角弯需要持续的转向力维持90度转弯
没有积分项 = 转弯力度不够 = 欠转 = 冲出去
```

### 问题 3：图像误差没有距离加权

你的 `calc_image_error()`（`image.c` 第939行）：
```c
for (uint8 i = 0; i < ROW; i++)
{
    err_sum += (mid_line[i] - COL / 2);
}
err = err_sum / ROW;  // 简单平均，120行等权
```

**远处和近处的权重一样！**

```
远处（行0-30）：看到直角弯的提前量 → 权重应该高
近处（行80-119）：已经在弯道里了 → 权重应该低

你现在：远处1行 = 近处1行 → 远处的提前预警被稀释
应该：远处权重3.0，近处权重0.5 → 提前发现弯道
```

你的代码里其实有一个注释掉的加权版本（第968-1003行），权重是 `near=3.0, mid=1.5, far=0.5`——但这恰好**反了**（应该远处权重高），所以被注释掉是对的。

### 问题 4：陀螺仪只用来减速不用来辅助转向

```c
steer_value = ... - (gyro * gkd) / 100;
//                             ↑ 减号 = 抵抗旋转
```

**陀螺仪的作用是"刹车"，不是"加油"。** 在直角弯时，车子需要快速旋转，但陀螺仪检测到旋转后反而减少了转向输出。

```
直角弯时的理想状态：
  图像说：往右转！(error > 0)
  陀螺仪说：正在往右转！(gyro > 0)
  PID输出：kp*error - gyro*gkd/100 = 转向力 - 阻尼力

  如果阻尼太大 → 转向力被抵消 → 转不过来 ❌
```

### 问题 5：转弯完成判定太宽松

```c
// 左转完成条件：
if (yaw_total <= yaw_target + 20.0f)  // 容差20度！
// 右转完成条件：
if (yaw_total >= yaw_target - 20.0f)
```

目标转90度，但只要转了70度就认为完成了。高速时车还没转够就退出转弯了。

## 三、网友经验总结

### 最常见的解决方案（按优先级排序）

| 优先级 | 解决方案 | 你的情况 | 效果 |
|:---:|---------|---------|------|
| **1** | **弯道前减速到30%-50%** | ❌ 代码被注释掉了 | 最关键，必须做 |
| **2** | **分段PID参数**（直道/弯道用不同参数） | ❌ 没有 | 弯道需要更大的Kp和Kd |
| **3** | **前馈+PID组合控制** | ❌ 只有PID | 提前计算转向角，PID只做修正 |
| **4** | **动态前瞻距离**（速度越快前瞻越远） | ❌ 固定平均 | 提前发现弯道 |
| **5** | **差速辅助转弯** | 部分有（差速PID） | 内侧轮减速帮助旋转 |
| **6** | **补线策略**（丢线时用历史数据补） | 有change_line | 转弯时赛道线消失的处理 |

### 网友的调参口诀

```
直道求稳：Kp小，Kd大（抑制震荡）
弯道求快：Kp大，Kd大（快速响应+抑制冲出）
高速降Kp：速度越快，Kp应该越小（防止过调）
```

### 网友推荐的直角弯处理流程

```
发现直角弯（远处）→ 立即减速到30%速度
       ↓
进入弯道 → 切换弯道PID参数（Kp大，Kd大）
       ↓
弯道中 → 用陀螺仪辅助转向（不只是阻尼）
       ↓
转够90度 → 检测到新赛道线 → 恢复直道PID
       ↓
加速恢复
```

## 五、摄像头基础知识总结

### 5.1 摄像头参数

| 参数 | 你的值 | 含义 | 影响 |
|------|:---:|------|------|
| 分辨率 | 188×120 | 列×行 | 越高细节越多，但处理越慢 |
| 帧率 | 50-100fps | 每秒帧数 | 越高延迟越低，但曝光时间受限 |
| 曝光时间 | 512(默认)/1500(暗光) | 传感器接收光的时间 | 越长越亮，但帧率下降 |
| 增益 | 32(默认)/56(暗光) | 信号放大倍数 | 越大越亮但噪点多 |
| 视角 | 130° | 广角范围 | 越大看到越宽，但边缘变形大 |

### 5.2 帧率 vs 曝光时间关系

```
一帧的总时间 = 曝光时间 + 读出时间 + 传输时间

帧率 = 1000ms / 一帧总时间

曝光 512μs + 读出 2ms + 传输 1ms = 3.5ms → 最高 285fps
曝光 1500μs + 读出 2ms + 传输 1ms = 4.5ms → 最高 222fps
曝光 8000μs + 读出 2ms + 传输 1ms = 11ms → 最高 90fps

设定FPS=100时：每帧10ms
  如果总时间 > 10ms → 帧率自动下降
  如果总时间 < 10ms → 正常运行
```

### 5.3 Gamma校正

```
gamma < 1.0（如0.5）：暗处变暗，亮处不变 → 加大对比度
gamma = 1.0：无变化
gamma > 1.0（如2.0）：暗处变亮，亮处不变 → 增强暗区细节

暗光环境推荐 gamma = 2.0~3.0
正常光线推荐 gamma = 0.5~0.8
```

### 5.4 二值化（OTSU大津法）

```
OTSU原理：找一个阈值，使黑白两类像素的类间方差最大
  阈值太低 → 太多白色（反光也被当赛道）
  阈值太高 → 太多黑色（赛道被吃掉）

三段OTSU（你的方案）：
  远处用一个阈值，中间用一个，近处用一个
  → 解决远近光线不一致的问题
```

### 5.5 图像处理时间预算

```
帧间隔 = 1000 / FPS (毫秒)

50fps  → 帧间隔 20ms → 图像处理必须 < 20ms
100fps → 帧间隔 10ms → 图像处理必须 < 10ms

你的处理流水线耗时：
  image_binarize  ~1.5ms
  search_line     ~0.5ms
  node_proc       ~0.3ms
  calc_error      ~0.05ms
  合计            ~2.3ms ✅ 远低于帧间隔

加了去噪+反光抑制后：
  + denoise       ~1.0ms
  + reflect       ~0.3ms
  合计            ~3.6ms ✅ 仍然安全
```

### 5.6 前瞻距离

```
前瞻距离 = 车能看到的最远处赛道

影响前瞻的因素：
  1. 摄像头安装高度 → 越高看得越远
  2. 摄像头俯仰角 → 越俯视近处清楚，越平视远处清楚
  3. 图像处理区域 → 行0-30是远处，行80-119是近处

速度越快 → 需要越远的前瞻 → 提前发现弯道

动态前瞻（模块7已移植）：
  直道时白色区域高 → 前瞻远 → 看得远
  弯道时白色区域低 → 前瞻近 → 看得准
```

### 5.7 反光处理

```
反光来源：
  1. 车身元器件反光（LED、电容、螺丝）
  2. 赛道外地面/墙壁反光（130°广角拍到）
  3. 光线直射摄像头

处理方案（已移植4种）：
  方案A：固定区域屏蔽（简单但丢前瞻）
  方案B：ROI安全区域（只在中间算）
  方案C：白点超标→边界收缩（草莽+知乎）
  当前方案：标定宽度×2判定（草莽方案，只改mid_line）
```
