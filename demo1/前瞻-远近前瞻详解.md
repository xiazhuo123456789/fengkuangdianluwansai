# 疯狂电路 — 前瞻（远近前瞻详解）

> 结合 RT1064 逐飞源码，全程大白话 + 代码逐行拆解，彻底讲透「远近前瞻」

---

## 一、先抛开代码，生活化形象类比（开车 = 智能车，一眼看懂）

### 1. 什么是「前瞻」？

你坐在车里开车，眼睛分两个视野看路：

| 前瞻类型 | 类比 | 作用 |
|----------|------|------|
| **近前瞻**（近处点，代码固定 0.25m） | 只看车头前 30 厘米地面 | 只管车身有没有左右跑偏、压线，保证直道车身稳稳居中，不左右飘 |
| **远前瞻**（远处点，代码可调 `aim_distance`，默认 0.58m） | 看车头前面半米开外的路 | 专门看前方有没有直角/弯道，提前预判转弯，提前打方向，不会冲到直角跟前才猛掰舵 |

### 2. 为什么必须两个一起看，不能只看一个？

| 方式 | 问题 |
|------|------|
| 只看近处 | 直道很稳，一遇到 90° 直角，来不及反应，直接冲线 |
| 只看远处 | 车身左右疯狂抖动，一点点光线变化就大幅度打舵，跑直道全程晃 |
| ✅ **远近加权融合** | 直道偏重近处稳车身，直角弯道偏重远处提前转向，兼顾两种工况 |

### 3. 代码里的赛道中线数组是什么？

经过图像处理流水线，最终输出归一化中线数组 `rptsn[float 二维点集]`

**数组下标规则（核心，看懂这个就全通）：**

```
rptsn[0]   = 离小车车头最近的中线点（脚底下）
rptsn[10]  = 车头往前一段距离
rptsn[30]  = 画面最远处、最远前瞻点
```

> 📌 **下标数字越大 = 离车越远，看得越前。**

## 二、从代码里抠出全部相关变量，先认参数

```c
sample_dist     // 重采样后，相邻两个中线点的实际物理距离，单位米。例：0.02 = 每2厘米一个点

near_dist=0.25  // 近前瞻固定 0.25 米，只管近处居中
```

## 三、代码完整流程：怎么取近点、远点（逐行拆解）

### 步骤1：把「米数距离」换算成数组下标

```c
aim_idx = clip(aim_distance / sample_dist, 0, max_idx);
aim_idx_near = clip(near_dist / sample_dist, 0, max_idx);
```

**举个实例代入数字：**

- `sample_dist = 0.02m`（两点间隔 2cm）
- `aim_distance = 0.58m`

| 计算 | 公式 | 结果 | 含义 |
|------|------|------|------|
| 远点下标 | 0.58 / 0.02 = 29 | `aim_idx = 29` | `rptsn[29]` 就是 0.58 米远处赛道点 |
| 近点下标 | 0.25 / 0.02 = 12.5 → 四舍五入 | `aim_idx_near = 13` | `rptsn[13]` 车头前 0.25 米近处点 |

> `clip(a, 0, 最大值)`：防止距离设置过大，下标超出数组长度导致程序崩溃，强制锁死在合法范围。

### 步骤2：取到点坐标，计算「偏差 error」（夹角，就是要打多少舵）

**坐标系前置规则（摄像头画面）：**

```
Y轴向下 = 小车前进方向
X轴左右 = 车身偏移
cx, cy   = 摄像头镜头中心点，等效小车车头坐标
```

**远前瞻偏差计算（远点误差）：**

```c
error = atan2(rptsn[aim_idx].x - cx, rptsn[aim_idx].y - cy);
```

**形象翻译：**

从车头 `(cx, cy)` 拉一条直线到远处拐点 `rptsn[29]`，这条线和小车正前方的夹角就是 `error`。

| error 值 | 含义 |
|----------|------|
| error = 0 | 远处赛道笔直正对车头，不用打方向 |
| error = +10° | 远处赛道往右拐，舵机向右打 |
| error = -12° | 远处赛道往左拐，舵机向左打 |

**近前瞻偏差计算（近点误差）逻辑完全一致：**

```c
error_near = atan2(rptsn[aim_idx_near].x - cx, rptsn[aim_idx_near].y - cy);
```

`error_near` 是车头近处 0.25 米赛道和车身的夹角，只管当下车身有没有跑偏、压线。

## 四、远近两个偏差怎么融合使用？核心 `far_rate` 权重（直角拐弯关键）

**代码逻辑：**

```c
final_error = error_far * far_rate + error_near * (1 - far_rate);
```

### 分两种场景形象解释

#### 场景1：直道，无直角（`Lpt0_found = false`，`far_rate = 0.4`）

- 近点权重更高（60%），算法优先听从近处赛道指令
- **效果**：车身死死贴在赛道中间，不会左右大幅度晃动，跑直道非常稳

#### 场景2：前方识别到 90° 直角（`Lpt0_found = true`，`far_rate = 0.75`）

- 远点权重拉到 75%，算法优先听远处拐点的指令
- 哪怕车头近处暂时有点偏移，也要优先跟随远处直角的走向，提前大幅度预打方向
- **解决痛点**：只看近处的话，到直角跟前误差才变大，猛打舵直接冲出赛道；加重远点权重，车离拐点还有一段距离就提前转向，顺滑过完 90° 弯

## 五、结合直角过弯完整走一遍代码时序（实战场景）

### 前置已知参数

```
sample_dist = 0.02m
aim_distance = 0.58m
近点 0.25m
远点下标 29，近点下标 13
find_corners() 检测到 L 直角，far_rate = 0.75
```

### 运行时序

```
1. 远点 rptsn[29] 是 90° 拐点，计算 error = -12°（远处赛道大幅左拐）

2. 近点 rptsn[13] 几乎正对车头，error_near = -2°

3. 加权融合计算总偏差：
   final_error = -12 × 0.75 + (-2) × 0.25 = -9 - 0.5 = -9.5°

4. PID 根据 -9.5° 输出左打舵角度，小车提前向左转向
```

> ⚠️ 如果不加权重、只看近点，误差只有 -2°，只会轻微打舵，冲到直角跟前来不及转弯直接出界。

## 六、你提的几个疑问逐一对应代码回答

### 1. "前端有多少？前瞻距离怎么设置？"

| 前瞻类型 | 设置 | 说明 |
|----------|------|------|
| 近前瞻 | 固定写死 0.25 米 | 不用调 |
| 远前瞻 `aim_distance` | 上位机可调，范围 0.01~1 米 | 需要根据赛道调节 |

**远前瞻调节参考：**

| 赛道类型 | aim_distance | 说明 |
|----------|-------------|------|
| 直道为主 | 0.4~0.5m | 不需要看太远 |
| 直角、S 弯多 | 0.55~0.65m | 看得更远，提前预判 |

> 📌 前瞻越远，预判越早，直角越顺滑；但太远画面顶部噪点会干扰，容易乱打方向。

### 2. "怎么取的点？" 一句话总结代码逻辑

```
1. 先规定每 sample_dist 米一个中线点
2. 想要看多远，就用「目标距离 ÷ sample_dist」算出对应数组下标
3. clip 锁死下标不越界，取出该点 XY 坐标
4. 和车头 cx/cy 坐标计算向量夹角，得到偏差 error
```

### 3. "为什么不能只用单前瞻？"

| 方式 | 结果 |
|------|------|
| 只看近处（0.25m） | 直道稳，直角来不及转向冲出去 |
| 只看远处（0.58m） | 车身左右飘，轻微光线变化就大幅度打舵，全程抖动 |
| ✅ 远近加权 | 直道稳、弯道提前转向，兼顾两种工况 |

### 4. 和直角拐弯的强关联（代码核心设计）

`find_corners()` 函数识别 L 型直角拐点（70°~140° 局部弯曲角度）后，自动拉高 `far_rate` 远前瞻权重，算法优先跟随远处拐点走向预打舵。

> 🎯 **这就是这套代码过直角不飞的核心逻辑。**

## 七、补充配套前置代码依赖（前瞻能正常运行的前提）

| 步骤 | 函数 | 作用 |
|------|------|------|
| 1 | `process_image()` | 图像流水线，输出平滑、等距采样的左右边线 |
| 2 | `track_leftline / track_rightline` | 左右边线合成赛道中线 `rptsc` |
| 3 | `resample_points2` | 等距重采样，保证每个点间隔固定 `sample_dist` 米，前瞻距离换算下标才准确 |

> ⚠️ 缺少任意一步，前瞻取点、直角预判都会失效。

## 八、改进版 `calc_image_error()` 函数（替换原版）

这个函数在你的工程里，不在 demo 目录。直接给你改好的版本，替换进去：

```c
void calc_image_error(void)
{
    float err = 0;
    static float err_last;

    // ── 第一步：分组计算近处/远处偏差 ──
    float err_near = 0;   // 近处组（车头附近）
    float err_far  = 0;   // 远处组（画面上方）
    int   near_cnt = 0;
    int   far_cnt  = 0;

    for (uint8 i = 0; i < ROW; i++)
    {
        float single_err = mid_line[i] - COL / 2;

        if (i < ROW / 2)
        {
            // 近处：画面下半部分，离车近
            err_near += single_err;
            near_cnt++;
        }
        else
        {
            // 远处：画面上半部分，离车远
            err_far += single_err;
            far_cnt++;
        }
    }

    // 各自取平均
    err_near /= (near_cnt > 0) ? near_cnt : 1;
    err_far  /= (far_cnt  > 0) ? far_cnt  : 1;

    // ── 第二步：根据弯道情况动态调 far_rate ──
    float far_rate;
    if (/* 检测到弯道/直角的条件 */)
    {
        // 弯道：远处权重拉高，提前转向
        far_rate = 0.75f;
    }
    else
    {
        // 直道：近处权重拉高，稳车身
        far_rate = 0.4f;
    }

    // ── 第三步：远近加权融合 ──
    err = err_far * far_rate + err_near * (1.0f - far_rate);

    // 一阶低通滤波（抑制噪声）
    err = err * 0.9f + err_last * 0.1f;
    err_last = err;

    // 限幅保护
    if (err >= 55)  err = 55;
    if (err <= -55) err = -55;

    image_err = err;
}
```

### 改动对比

| 项目 | 原来 | 现在 |
|------|------|------|
| 计算方式 | 所有行平等求和 | 近处/远处分组求平均 |
| 权重 | 没有，全一样 | `far_rate` 动态加权 |
| 弯道 | 和直道一样 | 远处权重高，提前反应 |
| 直道 | — | 近处权重高，车身稳 |

### `/* 检测到弯道/直角的条件 */` 常见填法

```c
// 方案1：看远处偏差是否突然变大（远处偏差 > 阈值 = 前方有弯）⭐ 推荐先试这个
if (fabsf(err_far) > 15.0f)

// 方案2：你现有的赛道元素识别标志
if (cross_type != CROSS_NONE || circle_type != CIRCLE_NONE)

// 方案3：看偏差变化率（连续几帧偏差在增大 = 正在入弯）
if (fabsf(err_far - err_far_last) > 5.0f)
```

> 📌 **方案1 最简单直接，你先用这个试，不行再换。**
